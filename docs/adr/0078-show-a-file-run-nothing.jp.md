# ADR 0078: 変更ファイルはファイルマネージャで表示し、何も実行しない

## Status

Accepted (2026-11-02)。[ADR 0062](0062-open-with-editors.jp.md) と [ADR 0070](0070-open-in-working-tree.jp.md) を改める。

## Context

変更ファイルのメニューには「エディタで開く」があり、ファイルを OS の既定のハンドラに渡していた。Windows では、そのハンドラは `.cmd`、`.bat`、`.exe`、`.js` のファイルを開かずに実行する。2026-11-02 に、リポジトリにコミットされた `run.cmd` が、これを選ぶと実行され、マーカーのファイルを書いた。ADR 0070 は、既定のハンドラが開くファイルは実行するプログラムでもありうると記しながら、そのままにしていた。つまり、リポジトリのファイルの拡張子が、実行するプログラムを選んでいた。これは [QUALITY](../QUALITY.jp.md) の、リクエストが実行するプログラムを選べるのはユーザーが設定した一覧の中の位置によってだけ、という決まりに反する。

リポジトリのフォルダも同じ経路を通っていた。macOS の `open` は、プログラムを持つ `x.app` という名前のフォルダを実行する。リポジトリや submodule は、そうした名前にできる。Windows では、ハンドラは `cmd /c start` を通っていた。2026-11-02 に試したところ、フォルダの隣のスクリプトは実行されなかったが、ここでシェルを通す理由はなかった。

## Decision

- **ファイルは既定のハンドラではなく、ファイルマネージャに渡す。** `/api/reveal` は、ファイルをエクスプローラ（`explorer /select,`）や Finder（`open -R`）で選んだ状態で表示する。そのほかでは、ファイルを選べる手段がないので、ファイルのあるフォルダを開く。パスについての ADR 0070 の検査は、これまでどおり先に行う。
- **リポジトリのフォルダも同じようにする。** エクスプローラで直接開き、Finder では選んだ状態で表示する（`open -R`）。そのほかでは、これまでどおりオープナーにフォルダを渡す。
- **メニューには、起こることを書く。** ファイルの項目は、ドロワーと同じ「ファイルマネージャで開く」とする。編集のためにファイルを開くのは、ユーザーが並べたエディタと、Windows ではシステムのアプリ選択の役目とする。

## Consequences

- この項目を選んでも、ファイルは既定のアプリでは開かなくなる。
- リポジトリの中のプログラムは表示されるだけで、実行されない。
- macOS では、リポジトリを表示すると、開くのではなく、親フォルダの中で選んだ状態で表示する。
- Linux では、開いたフォルダの中でファイルは選ばれない。
- 単体テストでエクスプローラの引数と、パスに対して選ぶフォルダを確かめる。Linux のテストでは、渡されたものを記録するオープナーを用意して動いているサーバに頼み、実行可能なファイル、`.`、リポジトリのどれでも、渡されるのがリポジトリのフォルダであることを確かめる。Finder の経路を確かめるテストはない。2026-11-02 に、Windows で、動いているサーバに `run.cmd` とそのフォルダの表示を頼み、マーカーのファイルが現れないことを確かめた。
