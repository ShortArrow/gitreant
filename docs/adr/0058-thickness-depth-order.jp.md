# ADR 0058: 厚みを奥行きの順に描き、加えた側を手前にする

## Status

Accepted (2026-10-29)

## Context

グラフの厚み（[ADR 0044](0044-graph-thickness.jp.md)）は、コミットのノードの写しを、加えた行の数だけ左上へ、削った行の数だけ右下へ積み、「ノードと辺の後ろに」、各側を「1 つの半透明の形として」描いていた。左上は見る人の手前、右下は奥に読めるのに、加えた側はノードの背後に、さらに削った側の背後にも描かれていたので、絵が示す奥行きと描く順が食い違っていた。また、同じ側ではすべてのレーンが 1 つの形にまとまるので、あるブランチの厚みが別のブランチの厚みと交わる所で、どちらが手前かを示すものがなかった。

## Decision

- **奥から順に、削った側、エッジ、ノード、加えた側とする。** 削った側は今までどおりエッジの背後に、加えた側はノードの手前に描く。厚みはポインタのイベントを受けないままなので、加えた側の下のノードも、今までどおりクリックやホバーができる。
- **レーンごとに 1 つの形にし、右のレーンほど手前にする。** 同じ側では、レーンごとに柱とフカヒレを 1 つの半透明の形にまとめ、左のレーンから右のレーンへ順に描く。フカヒレは、つなぐ 2 つのレーンのうち右のレーンに属する。同じレーンでは、フカヒレを柱の上に描く。
- **輪郭で前後を示す。** 各レーンの形に、その側の色を濃くした細い輪郭を付ける。手前の形が奥の輪郭を覆うことで前後が分かる。同じ色の半透明の形 2 つは、どちらの順に重ねても同じに見えるからである。

## Consequences

- 厚みをレーンごとに分ける処理は純粋関数にし、単体テストで確かめる。側とエッジやノードとの順、側の中のレーンの順は、E2E テストで確かめる。
