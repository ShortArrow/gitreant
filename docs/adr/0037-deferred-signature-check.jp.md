# ADR 0037: グラフを先に出し、署名は後から確かめる

## Status

Accepted (2026-10-22)

## Context

[ADR 0011](0011-signature-verification.jp.md) は、署名の検証をビューの読み込みの中で行う。読み込みは履歴をたどったあと、まだ判定のない署名付きコミットについて `git log` を 1 回実行し、その終了を待つ。git はこの中で、コミットごとに gpg を呼ぶ。履歴のほとんどが署名付きのリポジトリでは、最初の読み込みが全コミットぶん gpg を待つ。コミット 2,668 件、うち署名付き 2,376 件のリポジトリでは、履歴をたどるのは 1 秒もかからないのに、この待ちが約 16 秒になる。その間、解析中のカウンタ（[ADR 0023](0023-progressive-loading.jp.md)）には知らせることがなく、最初の値のまま止まり、最後にグラフがまとめて現れる。

## Decision

- **ビューの読み込みは署名を待たない。** キャッシュ済みの判定はこれまでどおりビューに付ける。gpg が使えるとき、まだ判定のない署名付きコミットには、ビューで `verifying` の印を付ける。
- **署名は読み込みのあと、バックグラウンドで確かめる。** サーバは、判定待ちのコミットを表示順に 256 件ずつ確かめる。1 つのリポジトリで同時に走るのは 1 回だけである。1 バッチ終わるごとに、判定をキャッシュし、コマンドをコマンドログ（[ADR 0009](0009-command-log.jp.md)）に記録し、リポジトリを名指しした `verified` イベントを送る。クライアントはそのリポジトリのビューを読み直す。コマンド、`%G?` の読み方、キャッシュは ADR 0011 のままである。
- **キャッシュの消去は、走っている検証より優先する。** 「署名を再検証」はキャッシュを消す。その前に始まったバッチは判定を保存せず、次の読み込みでそのコミットをもう一度確かめる。
- **バッジの代わりに脈動するスケルトンを出す。** `verifying` のコミットの行には、バッジと同じ大きさで脈動する仮置きを出し、詳細ペインには署名を確かめている最中だと出す。`prefers-reduced-motion` のときは脈動させない。署名のないコミットには、これまでどおり何も出さない。

## Consequences

- グラフは、履歴をたどり終えた時点で現れる。バッジは上から、1 バッチずつ埋まる。
- コマンドログの記録は、読み込みごとに 1 件から、バッチごとに 1 件になる。
- gpg がなければ `verifying` の印は付かず、署名付きのコミットはこれまでどおり「Signed」と出る。
