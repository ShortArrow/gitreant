# ADR 0064: 動いているサーバは秘密を持つことを示してから信頼する

## Status

Accepted (2026-10-29)

## Context

`gitreant` は、ポートに gitreant が応えるかを尋ねて、動いているサーバを見つける。そのうえで、リポジトリを転送し、一覧を読み、記録にある秘密を付けてページを開く（[ADR 0063](0063-request-token.jp.md)）。この問いには何でも応えられる。サーバが止まった後は、ほかのアカウントのプログラムがポートを取り、問いに応えられる。そうすると `gitreant` は、リポジトリのパスと記録の秘密をそれに送り、開くべきリポジトリをそれから読み、そのページでブラウザを開いてしまう。そのページは gitreant のものになりすませる。

## Decision

- **サーバは秘密を明かさずに、持っていることを示す。** `/api/ping?challenge=<hex>` と尋ねられたサーバは、目印とともに `HMAC-SHA256(secret, challenge)` を返す。答えは秘密について何も明かさず、毎回新しい問いを使うので、古い答えは使えない。
- **CLI は信頼する前に尋ねる。** リポジトリを転送する前、再起動のために動いているサーバの一覧を読む前、ページを開く前に、CLI は OS の乱数源から問いを作り、答えをサーバの記録にある秘密と一定時間で照らし合わせる。示せないサーバや記録のないサーバは、利用者のものではない。CLI はそう伝えて止まり、何も送らず、何も開かない。
- **サーバを見つける方法は変えない。** 問いのない ping は、gitreant が応えることだけを示すままにする。ポートが使われているかを知るためと、止まったサーバの記録を片付けるためである。

## Consequences

- 証明は公開された HMAC-SHA256 のテストベクタで単体テストする。サーバのテストで正しい秘密は通り、間違った秘密は通らないことを確かめる。CLI のテストでは、gitreant と同じように ping に応えるプログラムに向けて `gitreant` を動かし、何も送らず何も開かないことを確かめる。
- サーバの停止や署名の再検証は、これまでどおり記録の秘密だけで行う。秘密を持たないサーバは、どのみちそれを拒む。
