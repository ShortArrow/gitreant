# ADR 0053: 変更ファイルの一覧でバイナリファイルを示す

## Status

Accepted (2026-10-28)

## Context

詳細ペインは、コミットで変わったファイルを、それぞれが加えた行と削った行の数とともに並べる。バイナリファイルには数える行がないので `+0 −0` と出ていた。これは、空のファイルを加えた場合や、中身を変えずに名前だけ変えた場合など、行を加えも削りもしなかったテキストファイルと同じ表示になる。2 つを見分けるには、「バイナリファイル — テキスト差分はありません。」と出る差分を開くしかなかった。どのファイルの差分をバイナリとするかは、差分ペインのためにすでに決めてある（[ADR 0033](0033-diff-attribute.jp.md)）。`diff` 属性を先に見て、なければ先頭近くの NUL バイトで判断する。作業ツリーの追跡中のファイルは git 自身の diff が判断し、読み込めないほど大きい未追跡のファイルはバイナリとして扱う。

## Decision

- **一覧では、行数の代わりに「バイナリ」と出す。** バイナリファイルの行には、改行コードのラベルと同じようなラベルを付け、数える行がないので `+N −M` は出さない。
- **差分ペインと同じ規則にする。** 一覧でバイナリとするのは、差分がバイナリになるファイルとちょうど同じにする。コミット、未コミットの変更（追跡中のバイナリファイルには git が両方の数に `-` を出す）、2 つのコミットの比較のいずれでも同じとする。
- **一覧の各ファイルが印を持つ。** サーバはこの印をファイルとともに送り、偽のときは省く。改行コードだけの変更の印と同じ扱いとする。

## Consequences

- バイナリファイルの見分けは、コミットと作業ツリーについてはアダプタのテストで、一覧については E2E テストで確かめる。
