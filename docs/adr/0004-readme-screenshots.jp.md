# ADR 0004: READMEスクリーンショットは宣言的フィクスチャから自動生成する

## Status

Accepted (2026-07-09)

## Context

OSSとして公開するREADMEにSPAの画面を載せたい。手動キャプチャには問題がある。

- UIが変わるたびに構図・テーマ・ウィンドウサイズを揃えて撮り直す必要があり、更新が滞って画面と実装が乖離する。
- 見栄えの良いブランチ分岐構造を持つリポジトリを毎回手作業で用意するのは再現性がなく、コミットメッセージや作者名の写り込みも制御できない。

## Decision

- スクリーンショットは Playwright で自動生成し、`pnpm screenshot` でいつでも同じ構図で再生成できるようにする（`docs/images/` にコミット）。
- 被写体のリポジトリは **宣言的シナリオ**（`frontend/screenshot/scenario.ts` の branch / commit / merge ステップ列）として記述し、ビルダー（`frontend/screenshot/build.ts`）が決定的なタイムスタンプで実リポジトリに変換する。分岐構造を変えたいときはシナリオを編集するだけでよい。
- dark / light の両テーマを撮影し、README では `<picture>` と `prefers-color-scheme` で出し分ける。
- 生成specは撮影と同時に構図の前提（レーン数・曲線エッジの存在・コミット数）をアサートし、シナリオの劣化を検知する。
- フィクスチャ生成・サーバ起動のヘルパは E2E と共有する（`frontend/e2e/git.ts` / `frontend/e2e/server.ts`）。

## Consequences

- UI変更後は `pnpm screenshot` の再実行だけで画像が現行UIに追従する。
- 撮影対象はフィクスチャなので、実リポジトリの内容が写り込む心配がない。一方で「実プロジェクトの画面」ではない演出上のリポジトリである。
- 画像はバイナリとしてリポジトリに残るため、無闇な再生成はdiffを大きくする。見た目が変わったときだけ再生成してコミットする。
