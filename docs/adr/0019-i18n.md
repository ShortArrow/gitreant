# ADR 0019: Hand-rolled typed dictionaries for i18n, language switched in settings

## Status

Accepted (2026-07-15)

## Context

UI copy was a mix of English and Japanese, so we want to let users
pick a language and make it consistent. There are currently just
under 70 strings, with no advanced requirements such as plurals or
number formatting.

## Decision

- Do not add a library (react-i18next etc.); implement with
  **typed TypeScript dictionaries** (en / ja in `i18n.ts`, with
  `MsgKey` checked at compile time) and `useT()` (via
  SettingsContext). Placeholders are simple `{name}` substitution
  only.
- The language setting has three values — **Auto (Japanese if
  `navigator.language` is a ja variant, English otherwise) /
  English / 日本語** — changed from the settings dialog and saved to
  localStorage (the ADR 0015 pattern).
- **Domain terms shared with GitHub are not translated**: badges
  (Signed / Verified / Unverified / HEAD), signature type labels
  ("Signed (OpenPGP)" etc.), and the contents of the command log
  (executed command strings and records of user actions). The log is
  a record of what was executed, not display copy.
- Key parity between the two dictionaries is verified with Vitest.

## Consequences

- Adding a supported language takes one new dictionary plus one line
  for the settings option.
- Plural handling uses the naive approach of two keys for English
  "1 file / N files". If more languages break this down, we will
  decide on introducing something ICU-MessageFormat-like in a
  separate ADR at that point.
