# ADR 0061: 差分の前後のファイルを読めるようにする

## Status

Accepted (2026-10-29)

## Context

差分ペインは、変更されたファイルをハンクとして表示し、変更の前後に 3 行の文脈を付け、ハンクの間を `@@` の行で区切る。変更の少し上や少し下、またはそのコミットのファイル全体を読むには、gitreant を離れて別のツールに移るしかなかった。サーバにはファイルの内容を読む手段がなく、どのルートも差分を返していた。

## Decision

- **サーバは差分の新しい側のファイルを読む。** ルートは、差分が行き着く側のパスの内容を返す。コミットならそのコミットのツリー、2 つのコミットの比較なら後のコミット、未コミットの変更なら作業ツリーで、作業ツリーは未追跡のファイルと同じ大きさの上限で読む。バイナリのファイル、大きすぎて読めないファイル、その側にないパスは何も返さない。
- **隠れた行は 20 行ずつ開く。** 変わらない行が隠れている所、つまり最初のハンクの前、2 つのハンクの間、最後のハンクの後では、`@@` の行の代わりに、隠れた行の数を示して開く行を置く。次のハンクから上へ、前のハンクから下へ、20 行ずつ開ける。残りが 20 行以下ならまとめて開く。開いた行は変わらない行なので両側で同じに読め、古い側の行番号は隣のハンクに合わせる。
- **「全体を表示」はすべての隠れた行を開く。** 各ファイルの見出しのボタンで、ファイル全体を、変更をその位置に示したまま表示する。
- **内容は最初に開くときに読む。** ファイルの内容は、その隠れた行を初めて開くときにだけ問い合わせる。各差分は新しい側の行数を持つので、最後のハンクの後は、何も読む前から、行が残るときだけ示す。行数が分からないときは、隠れた行の数を示さずに開けるようにする。内容を読めないファイルは、隠れた行を閉じたまま、そう示す。ファイルの最初の行から始まるハンクの上には隠れた行がないので、`@@` の行を付けない。
- **開くと行の選択を解く。** 選択を数える行の並びが動くので、インラインと左右分割を切り替えるときと同じく解除する。

## Consequences

- 差分を表示する行と隠れた行に分けるのは、ハンク、ファイルの行、各所をどこまで開いたかの純粋関数にし、単体テストで確かめる。ルートはアダプタのテストで、ボタンは E2E テストで確かめる。
