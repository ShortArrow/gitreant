# ADR 0043: 加えた行と削った行を、時間に沿って足し上げたグラフにする

## Status

Accepted (2026-10-24)

## Context

[ADR 0041](0041-diff-stats-per-commit.jp.md) で各コミットが加えた行と削った行を数え、[ADR 0044](0044-graph-thickness.jp.md) でそれをグラフに沿った厚みとして見せた。どちらも、コードが時間とともにどう育ったかは見せない。ある期間に削ったより多く加えたのか、履歴がいつ止まっていたのかは分からない。

すべてのコミットを足すと、ブランチの変更を二重に数える。マージは最初の親と比べて数えるので、ブランチ上のコミットで一度、それを取り込んだマージでもう一度数えることになる。HEAD から最初の親だけをたどって足せば、どの変更も一度だけ数え、その差し引きは木の行数の増減と一致する。

## Decision

- **ペインごとの、別のモードにする。** ペインのヘッダーにボタンを置き、押すと行とそのグラフの代わりに累積のグラフを出す。もう一度押すと行の表示に戻る。選んだモードは保存せず、グラフを出している間は [ADR 0035](0035-graph-node-navigation.jp.md) の選択のキーを止める。
- **何を足すか。** ペインが読み込んだコミットのうち、HEAD の最初の親をたどる列を、古い順に足す。1 つ進むごとに、そのコミットが加えた行、削った行、その差を足す。和は、読み込んだ列のうち最も古いコミットで 0 から始めるので、履歴全体ではなく読み込んだ範囲を表す。まだ数えていないコミットは、数が届くまで何も足さない。数えている途中のコミットがあれば、その件数をグラフに出す。
- **3 本の線。** それまでに加えた行を緑で 0 から上へ、それまでに削った行を赤で 0 から下へ描き、その差（行数の増減）を本文の色の太い線で 2 本の間に描く。どれも、コミットごとに段が変わる階段状の線にする。ポインタを乗せたときの表示では、削った行は正の数のまま出す。
- **横軸は時間。** 横軸はコミットの時刻とし、静かな期間は平らな区間として見える。列の中で 1 つ前より時刻が早いコミットは、1 つ前の時刻に描き、線が前に進み続けるようにする。
- **軸と読み方。** 縦軸には切りのよい数の目盛りをいくつかと 0 の線を引き、横軸には最初と最後の日付を出す。線の上には凡例を置き、各線の名前をその色で示す。グラフにポインタを乗せると、最も近いコミットに縦線を引き、その日付と 3 つの和を出す。
- **ペインいっぱいに描く。** グラフはペインの大きさに合わせて描き、大きさが変われば描き直す。スクロールしないので、続きのコミットは読み込まない。

## Consequences

- 和はビューの純粋関数にして単体テストで確かめ、SVG に描く。グラフのライブラリは足さない。
- 履歴を一部しか読み込んでいないリポジトリのグラフは、読み込んだ最も古いコミットから始まる。行の表示で続きを読み込めば、過去へ延びる。
- [ROADMAP](../ROADMAP.jp.md) のカレンダーは、同じ時間の軸を使える。
