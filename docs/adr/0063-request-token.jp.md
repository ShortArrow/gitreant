# ADR 0063: 起動ごとに作る秘密を API のすべてのリクエストに求める

## Status

Accepted (2026-10-29)

## Context

サーバはループバックの名前宛てのリクエストだけに応え、ページからのリクエストは自分のページのものだけに応える（[ADR 0038](0038-loopback-request-guard.jp.md)）。それ以外は通す。ADR 0038 は「`Origin` のないリクエストは通す。ブラウザはこの種のリクエストに必ず `Origin` を付けるので、ないのは gitreant の CLI のようなクライアントであり、それはどのみちポートに直接届く」とした。これは 1 人が使うマシンでは成り立つ。ほかのアカウントとマシンを共有するときや、コンテナやサンドボックスとループバックを共有するときは、それらもポートに届く。`Origin` を付けなければ、サーバが表示するすべてのリポジトリを読み、書き換え、利用者のエディタ（[ADR 0062](0062-open-with-editors.jp.md)）でファイルを開くことを、利用者として行える。

## Decision

- **起動ごとに秘密を作る。** サーバは起動時に OS の暗号用の乱数源から 32 バイトを取り、16 進の 64 桁にする。乱数源が失敗したら起動しない。弱い秘密に切り替えることはしない。秘密はプロセスが続くあいだだけ有効で、再起動すると作り直す。
- **API のすべてのリクエストが持つ。** `/api/` へのリクエストは、`X-Gitreant-Token` ヘッダに秘密を持つ。ブラウザがヘッダなしで開くイベントのストリームは、クエリの `token` で持つ。比較は一定時間で行い、持たないリクエストには 401 を返す。`/api/ping` は gitreant が応えることを示すだけなので、秘密を求めない。CLI が動いているサーバを見つけられるようにするためである。ページ自身とそのファイルも求めない。リポジトリのデータを持たないからである。
- **ページは開くときのアドレスで受け取る。** `gitreant` はブラウザを `http://127.0.0.1:<port>/#token=<secret>` で開く。フラグメントはサーバに届かない。ページはそれを読み、履歴に残らないようアドレスから消し、自分のオリジンのストレージに保つ。ほかのポートのページはそのストレージを読めない。秘密なしで、または前の起動の秘密で開いたページは、コマンドから gitreant を開くよう示す。`gitreant list` は、各サーバのアドレスを秘密付きで表示する。
- **CLI はサーバの記録から読む。** 各サーバが書く記録（[ADR 0039](0039-server-records.jp.md)）に秘密を持たせ、利用者自身のディレクトリに置く。Unix ではファイルを持ち主だけが読めるようにする。CLI からサーバへのリクエストは、その記録の秘密を持つ。
- **署名付きのトークンにはしない。** 秘密が示すのは、リクエストがこの利用者のこの起動のページか CLI から来たことだけである。主張、期限、鍵を運ばないので、JSON Web Token は、運ぶもののないまま解析とアルゴリズムの選択を足すだけになる。

## Consequences

- 秘密のヘッダとクエリの読み取り、一定時間での比較、`/api/ping` とページを開いたままにすることは単体テストで確かめる。サーバのテストは秘密を送る。E2E テストは、ブラウザのすべてのリクエストに秘密を足すのではなく、秘密付きのアドレスからページを開き、ページが秘密を送ることを確かめる。
- 秘密を付けないアドレスのブックマークでは、使えるページは開かず、開き方を示すだけになる。
- gitreant がブラウザを開くとき、秘密付きのアドレスはブラウザのコマンドラインを通る。システムによっては、ブラウザの起動中にほかのアカウントがそれを読める。
