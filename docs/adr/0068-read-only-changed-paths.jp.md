# ADR 0068: 作業ツリーは未コミットの変更が挙げるパスでだけ読む

## Status

Accepted (2026-10-31)。[ADR 0061](0061-diff-context.jp.md) を改める。

## Context

ADR 0061 は「サーバは差分の新しい側のファイルを読む」と決め、未コミットの変更なら作業ツリーを読むとした。ルートは、普通の名前だけでできた相対パスで、そのディレクトリが作業ツリーの中に解決されるものなら、何でも受け付けていた。リポジトリ自身の `.git` ディレクトリもこれに当たるので、`.git/config` を求めると、設定の全文が返り、認証情報を含むリモートの URL もそこに入っていた。Windows では同じディレクトリが `.GIT`、`GIT~1`、`.git.` でも開けるので、名前で拒むには、ファイルシステムが受け付ける書き方をすべて挙げる必要がある。`.env` のような無視されたファイルも、差分ペインが表示することはないのに読めた。

差分ペインが作業ツリー側の内容を求めるのは、未コミットの変更が挙げるファイルだけである。その一覧は `git status` から作られ、無視されたファイルを含まない。ただし、ディスク上で `.git` に通じるパスは含みうる。Git for Windows はディレクトリのジャンクションをディレクトリとしてたどるので、`.git` へのジャンクションがあればその中のファイルを挙げ、無視されたディレクトリへのジャンクションがあれば、そのディレクトリのファイルをジャンクションの名前で挙げる。`.git./config` という名前のインデックスの項目は、書かれたとおりに挙げられ、開くと `.git/config` になる。同じように、`inner/.git./config` は作業ツリーの中に入れ子になったリポジトリの `.git` を開き、`.git.` はリンクされた worktree の `.git` ファイルを開く。

## Decision

- **作業ツリーは、未コミットの変更が挙げるパスでだけ読む。** パスは、そのリポジトリについて `git status` が報告するものと完全に一致したときだけ読む。それ以外のパスは、存在しないパスと同じく何も返さない。
- **パスの途中のディレクトリがリンクやジャンクションであれば読まない。パスが作業ツリーの下で解決される先のどの部分も、ディレクトリでもファイルでも、大文字小文字を問わず `.git` という名前であってはならない。** 作業ツリーの下に解決されないパスは何も読まない。パスそのものがリンクのファイルはリンク先の文字列として読むので、そのディレクトリだけを解決する。これは、パスのディレクトリが作業ツリーの中に解決されることを確かめていた検査に代わる。
- コミットのツリーを読む側は変えない。そちらはディスク上のファイルではなく git のオブジェクトを読む。

## Consequences

- 作業ツリー側を読むたびに、`git status` を 1 回多く実行する。読むのは、未コミットの差分の隠れた行を初めて開くときだけである。
- 差分ペインは一覧にあるファイルしか読まないので、表示は変わらない。
- アダプタのテストは、ルートの関数で `.git/config`、`.GIT/config`、無視されたファイル、変わっていないファイルを読み、何も返らないことを確かめる。Windows では、`.git` へのジャンクション、無視されたディレクトリへのジャンクション、そしてインデックスの項目を通しても読む。項目は、`.git./config`、入れ子のリポジトリの `inner/.git./config`、リンクされた worktree の `.git.` である。
- 作業ツリーの中に `.git` の下のファイルへのハードリンクがあれば、未追跡のファイルとして読まれる。ハードリンクを作るには作業ツリーへの書き込みが要り、それができればファイルを写すこともできる。
- リポジトリ自身の `core.worktree` が別のディレクトリから挙げたパスは、リポジトリのディレクトリの同じ名前で読まれる。この設定はリポジトリの内容であり、QUALITY はそれを信頼されたものとして扱う。
