# ADR 0081: リリースごとに人が受け入れ確認をする

## Status

Accepted (2026-11-03)。

## Context

リリース前の条件は、E2E 全件と `pnpm screenshot` の確認だった。どちらにも人は関わらず、利用者が最初に触れるものの一部に届かない。

- ブラウザがランチャーファイルを開くこと。これを行うテストはない。E2E は自分で作ったフォームを送り、単体テストはランチャーの中身を読むだけである。
- OS のフォルダ選択ダイアログとファイルマネージャ、利用者が指定するエディタ。
- ページが読める状態かどうか。`pnpm screenshot` が確かめるのは要素の有無である。0.4.0 の撮影は、コミットの本文が 2 行を覆った状態で成功し、これに気づいたのは画像を見た人だけだった。

## Decision

- **リリースには、人が [ACCEPTANCE](../ACCEPTANCE.jp.md) に合格することを必要とする。** 各ステップに合格の基準を書く。基準と違うステップがあれば、原因を直して影響するステップをやり直すまで、リリースしない。
- **合格の範囲は、通した OS とブラウザである。** バージョンを上げるコミットに、それらと通した人を記録し、配る OS のうち誰も試さなかったものを挙げる。それらは自動テストだけを根拠に配る。
- **文書の名前はチュートリアルにせず、受け入れ確認とする。** チュートリアルは利用者に教えるもので、ステップは学ぶために選ぶ。この文書のステップは自動テストが届かないものから選び、読み手はリリースする人である。

## Consequences

- リリースのたびに人の時間がかかり、エージェントが代わりに合格させることはできない。
- 画面やコマンドを変えると、この文書のステップも両言語で変わる。
- 利用者向けの入門にはならず、利用者は引き続き README から始める。
- ほかの環境でだけ届く動作、たとえば WSL の `--no-launcher` や Android で表示するアドレスは、誰かが試すことを選ばない限り、人の確認を受けない。
