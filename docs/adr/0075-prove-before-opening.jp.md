# ADR 0075: ページを渡す直前にもう一度サーバに秘密を示させる

## Status

Accepted (2026-11-01)。

## Context

`gitreant` は、自分のサーバがすでに動いていると、サーバが記録の秘密を持つことを示させ（[ADR 0064](0064-prove-the-secret.jp.md)）、渡されたリポジトリを追加させてから、ページのアドレスを表示し、ブラウザで開く。秘密を示させる接続と開く接続は別で、リポジトリを追加させるリクエストは、サーバがそれぞれを開き終えるまで待つ。

そのあいだにサーバが終了し、ほかのアカウントがそのポートを取ると、ブラウザはそのアカウントのページを開く。アドレスに含まれる秘密はもうどのサーバのものでもないが、そのページは service worker を残せる。その worker は、次にそのポートでそのブラウザにページを開いた gitreant の秘密を読む。これは [ADR 0073](0073-page-under-a-path-of-each-start.jp.md) が受け入れた場合である。その ADR は、ブラウザがそうしたページにたどり着く経路として古いタブ、ブックマーク、履歴を挙げているが、ここでは gitreant 自身がそこへ連れていくことになる。

CLI がどう確かめても、この隙間はなくならない。ブラウザが接続したときにポートを持っている相手に、ブラウザは届く。

## Decision

- **CLI は、リポジトリを追加させたあと、もう一度サーバに秘密を示させる。** ページのアドレスを表示したり開いたりする直前に行う。ポートがもう秘密を示せないときは何も開かず、そのポートがもう秘密を示せないと伝える。追加させたリポジトリは追加されたままになる。

## Consequences

- 最後に秘密を示させてから開くまでの隙間には、サーバがリポジトリを開く時間が含まれなくなる。残るのは、アドレスを表示してブラウザを起動するあいだである。
- 残る隙間は、ADR 0073 が受け入れた場合と同じく受け入れ、ブラウザがそうしたページにたどり着く経路にこれを加える。
- CLI のテストで、最初に問われたときだけ秘密を示せるプログラムを相手に `gitreant` を動かし、秘密付きのアドレスを表示せず、失敗することを確かめる。
