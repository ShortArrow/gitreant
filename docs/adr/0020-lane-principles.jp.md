# ADR 0020: レーン割当は「HEADが左端の直線、分岐は右へ、マージは右から」

## Status

Accepted (2026-07-15)

## Context

従来のレーン割当は「最小の空きレーンを再利用」だけが方針で、履歴の形によってはブランチが基点の左に現れ、マージが左からも右からも入る「カオス」な絵になっていた。特に HEAD のブランチが最新コミットを持たない場合に顕著だった。

## Decision

domain のレイアウトに次の2原則を入れる（`layout` が `head` を受け取る）。

1. **スパイン固定**: HEAD の第1親チェーン（スパイン）はレーン0を予約し、常に左端の直線として描く。他のコミットはスパインのレーンを奪えず、スパインへ収束するエッジはレーン0を指す。
2. **マージは右から**: マージ親（第2親以降）の新規レーンは「マージコミットのレーンより右」の最小空きレーンに割り当てる。空きの再利用は同一方向内でのみ行い、左へ逆流させない。

分岐（fork収束）の経路は従来どおりだが、上記によりブランチは基点より右に置かれるため「右に向かって分岐して、左に向かってマージする」絵に揃う。

## Consequences

- チェックアウト中のブランチが常に読みの基準線になる。
- レーン再利用の抑制で幅が増える履歴もある（正しさ優先）。
- HEAD が表示対象に無い場合（detached 等で表示範囲外）は従来挙動。
