# ADR 0074: サーバの停止と署名の再検証の前にも秘密を示させる

## Status

Accepted (2026-11-01)。[ADR 0064](0064-prove-the-secret.jp.md) を改める。

## Context

[ADR 0064](0064-prove-the-secret.jp.md) は、CLI がリポジトリを転送する前、一覧を読む前、ページを開く前に、動いているサーバに記録の秘密を持つことを示させるようにした。サーバの停止と署名の再検証は対象から外した。この 2 つは、素の ping に応答があれば記録の秘密を送っていた。秘密を持たないサーバはどのみちそれを拒む、という理由である。

正しく終了しなかったサーバの記録は残る。ほかのアカウントは、サーバが去ったポートを取れる。そのとき `gitreant --shutdown`、`gitreant --shutdown --all`、`gitreant refresh` は、そのプログラムに記録の秘密を送っていた。その秘密はもうどのサーバのものでもなかったが、CLI は [QUALITY](../QUALITY.jp.md) が掲げる「サーバが秘密を持つことを示すまで何も送らない」に反し、サーバを停止したと表示していた。

## Decision

- **停止と再検証も、先に秘密を示させる。** どちらのリクエストを送る前にも、CLI はほかのリクエストと同じく、新しい問いへのサーバの答えを記録の秘密と照らし合わせる。示せないプログラムには何も送らず、どのポートが示せなかったかを伝える。
- **何も応答しないときは、そう伝える。** ポートに何も応答しないときは、秘密を問う前に、そこで gitreant が動いていないと伝える。

## Consequences

- CLI が秘密を付けて送るリクエストは、どれもその秘密を示させたあとに送る。
- ping には応答するが秘密を示せないプログラムがいるポートは、停止したとは伝えず、示せなかったと伝える。
- CLI のテストで、gitreant のように ping に応答するプログラムを相手に `refresh`、`--shutdown`、`--shutdown --all` がどれも失敗し、秘密も ping 以外のリクエストも送らないことを確かめる。何も応答しないときの表示も別のテストで確かめる。
