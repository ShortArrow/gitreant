# ADR 0072: ほかのアカウントに秘密を見せるブラウザは開かない

## Status

Accepted (2026-10-31)

## Context

`gitreant` は、サーバの秘密を含むページのアドレスでブラウザを開く（[ADR 0063](0063-request-token.jp.md)）。ほかのアカウントがプロセスのコマンドラインを読める Linux と macOS では、代わりに起動用ファイルをブラウザに渡すので、コマンドラインにはファイルの名前だけが載り、秘密は載らない。ところが、ブラウザが Linux のファイルを開けない WSL と、起動用ファイルを書けなかったときは、アドレスそのものをブラウザに渡していた。そのため、ブラウザを開くプログラムとブラウザが、ほかのアカウントの読めるコマンドラインに秘密を載せていた。[ADR 0071](0071-other-accounts-in-scope.jp.md) は、そうしたアカウントを範囲内とし、この二つの場合を塞ぐべき穴とした。ユーザーが `--no-launcher` を選ぶのとは違い、どちらもユーザーが選んだものではないからである。

秘密を含むアドレスは、サーバを起動した端末にすでに表示されており、それを読むのはユーザーだけである。

## Decision

- **アドレスも起動用ファイルも渡せないときは、ブラウザを開かない。** アドレスを渡してよいのは、ほかのユーザーのコマンドラインを読めるのが管理者だけの Windows と、`--no-launcher` を付けたときである。それ以外では、起動用ファイルだけを渡す。WSL と起動用ファイルを書けなかったときは、`gitreant` は、ブラウザを開かないこと、表示したアドレスを開くか `--no-launcher` を付けることを伝える。
- `--no-launcher` の意味は変えない。アドレスそのものを渡すことを、ユーザーが選ぶオプションである。

## Consequences

- WSL では、ブラウザは自動では開かなくなる。端末に表示されたアドレスでページを開け、`--no-launcher` を付ければ前の動作に戻る。
- ブラウザに何を渡すかは純粋な関数で決め、アドレスを渡してよいとき、起動用ファイルがあるとき、どちらもないときを単体テストで確かめる。
