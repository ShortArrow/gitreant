# ADR 0040: 列の色を、使用中の列を見て選ぶ

## Status

Accepted (2026-10-22)

## Context

レイアウトは色を順に配る。新しいブランチの先端、マージされたブランチ、stash はどれも次の番号を受け取り、フロントエンドは 8 色のパレットを繰り返して使う。そのため、ブランチの多いグラフでは、ブランチの位置に関係なく 8 本ごとに同じ色が使われ、隣り合う 2 本の列が同じ色になることがある。stash も番号を 1 つ受け取るので、その下のブランチの色はすべて 1 つずつずれる（[ADR 0036](0036-stash-node.jp.md)）。

列は、始まった行から空く行まで色を持つ。マージされたブランチの列はマージコミットで始まり、分岐点まで続くので、ブランチがマージされずにいた期間だけ使われる。つまり列は行の区間であり、上の行から順に、使用中の列が持っていない最小の色を配れば、使う色の数はどの選び方よりも少なくなる。

## Decision

- **使用中の列が持っていない最小の色。** 始まる列は、ほかの使用中の列が持っていない、パレットの中で最小の色を受け取る。列が使用中なのは、コミットを待っている間で、分岐の線が親に届くまで確保している間も含む。レイアウトはパレットの大きさ（`PALETTE_SIZE`、8）を知っていて、それを超える色は配らない。
- **その列が最後に持っていた色は使わない。** 空いた列で始まる列は、その列が終わったときの色を受け取らない。終わったブランチの下で始まる新しいブランチが、その続きに見えないようにするためである。
- **パレットを超えたら、隣と違う色。** 使用中の列がパレットの色の数より多いときは、両隣の列が持っていない最小の色を受け取る。
- **stash も同じ規則で選ぶ。** stash は、自分の列も含めて、使用中の列が持っていない最小の色を受け取る。

## Consequences

- 上にブランチが増えても色はずれない。列の色は、始まったときに使用中だった列だけで決まる。
- stash の色は、その行を描いた後は確保しない。そのため、stash の線が親に届く前にその下で始まる列が、同じ色を受け取ることがある。stash の線はたいてい 1 行ぶんしかない。
- ブランチの色が、この変更の前と変わることがある。
