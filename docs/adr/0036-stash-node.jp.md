# ADR 0036: stash を、乗っている線と見分けて描く

## Status

Accepted (2026-10-22)

## Context

`git stash` のエントリはコミットで、最初の親は stash したときに HEAD があったコミットである。レイアウトはこれをほかのコミットと同じに扱う。HEAD の上で stash すると、チェックアウト中のブランチ用に確保した列とその色をそのまま受け継ぎ、ノードもふつうのコミットと同じ塗りつぶしの丸になる。グラフではブランチのコミットが 1 つ増えたように見え、違うと分かるのは行の `stash` バッジだけである。

グラフのほかの印にはすでに意味がある。中抜きの輪は HEAD、破線の輪は未コミットの行である。破線は補助の線で、スカッシュマージした PR（[ADR 0018](0018-squash-merge-links.jp.md)）、stash の index と未追跡ファイルの内部コミット、未コミットの行から HEAD への線に使っている。グラフの線は 2px で、stash から親への線はたいてい 1 行ぶんしかないので、これらの破線と並べた点線は見分けにくい。

## Decision

- **専用の色。** stash は、どの列に入っても、新しいブランチの先端と同じく新しい色を受け取る。ノードと、最初の親への線はその色で描く。列の色はそのまま下の線に残すので、stash の下のブランチは stash がないときと同じ色で描かれる。レイアウトはノードに stash の印を付ける（ノードとコミットのビューの `stash`）。
- **輪の中のドット。** stash のノードは、その色の輪の中心に塗りつぶしのドットを置いて描く。vscode-git-graph と同じ描き方である。HEAD の輪は中が空いているので、ドットの有無で見分けられる。
- **線は実線のまま。** 最初の親への線は実際の親子関係なので、ほかの最初の親への線と同じく実線で描き、破線にはしない。

## Consequences

- 色は順に配るので、stash より下で始まるブランチの色は、ブランチが 1 本増えたときと同じく 1 つずつずれる。
- パレットは 8 色で、順に繰り返して使う。ブランチが多いと、stash が近くのブランチと同じ色になることはまだある。近くで使われている色を避けて選ぶ方式は、別の変更として [ROADMAP](../ROADMAP.jp.md) に置く。
