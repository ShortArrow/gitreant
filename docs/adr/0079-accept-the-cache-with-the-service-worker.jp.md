# ADR 0079: ほかのアカウントのページがキャッシュに残したものも、service worker と同じく受け入れる

## Status

Accepted (2026-11-02)。[ADR 0073](0073-page-under-a-path-of-each-start.jp.md)、[ADR 0076](0076-post-the-secret.jp.md) を改める。

## Context

[ADR 0073](0073-page-under-a-path-of-each-start.jp.md) は、ほかのアカウントのページが残した service worker が秘密を読むことを受け入れている。それでも、そのページがキャッシュに残した応答を gitreant のページから遠ざける手段が 4 つあった。ページのファイルを読む起動ごとのベースパス、秘密を含むアドレスの起動ごとのクエリ、ページの `Clear-Site-Data: "cache"`、API リクエストの `cache: "no-store"` である。

ページが応答をキャッシュに残せるのは、ほかのアカウントがポートを持っている間にブラウザがそのページを開いたときだけである。service worker の登録に必要なのも、それだけである。その worker はページを開く `POST` の中の秘密を読む（[ADR 0076](0076-post-the-secret.jp.md)）ので、キャッシュを使える攻撃者にキャッシュを使う必要はない。4 つの手段が塞いでいたのは、同じ条件で開いている 2 つの道の片方である。

それでも service worker が動かないブラウザでは、4 つの手段に意味が残る。MDN の文書の写しには、Firefox の非公開ウィンドウがそれに当たると書かれている。2026-11-02 に、Playwright がビルドした Firefox 151 をヘッドレスで `--private-window` 付きで起動し、攻撃者とサーバの両方を演じるローカルのプログラムに向けて試した。ウィンドウは非公開だった。`navigator.storage.getDirectory()` は、そこでは `SecurityError` で失敗し、通常のウィンドウでは成功した。そのウィンドウで登録した service worker は、通常のウィンドウと同じく `POST` の中の秘密を読んだ。4 つの手段がなければ、ページのファイルのアドレスに 1 年キャッシュされたスクリプトは、どちらのウィンドウでもページから秘密を読んだ。Safari は試していない。

## Decision

- **ほかのアカウントのページがブラウザのキャッシュに残した応答を受け入れる。** 条件は、ADR 0073 が service worker について挙げたものと同じである。
- **ページのファイルは、それがある場所から読む。** ベースパスは使わない。秘密を含むアドレスは `http://127.0.0.1:<port>/#token=<secret>` とし、クエリは付けない。
- **ページは、キャッシュの消去をブラウザに求めない。** API リクエストも、キャッシュを避けるよう求めない。
- **ページ自身の応答は `no-store` のままとする。** 秘密を含むことがあるからである。

## Consequences

- キャッシュされたスクリプトや `/` のページは、service worker が動くブラウザに限らず秘密を読める。ポリシーなどで service worker を止めたブラウザでは、これまで塞がれていた入口がキャッシュの分だけ開く。
- そうしたページが残したものについて言うことは 1 つになる。ブラウザの `127.0.0.1` のサイトデータを消せば、消える。
- `gitreant` は、ページのパスを名付けるための値を秘密から導かなくなる。
- 動いているサーバに対するテストで、ページにベースと `Clear-Site-Data` がなく、`no-store` のままであることを確かめる。単体テストでアドレスを確かめる。
