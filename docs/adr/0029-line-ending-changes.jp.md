# ADR 0029: 改行コードの変更は行末の印とファイルのラベルで示す

## Status

Accepted (2026-10-01)

## Context

Windows の git（`core.autocrlf=true`）で展開した作業ツリーを WSL の git から見ると、全ファイルが「変更あり」になる。中身は改行コードの違い（LF と CRLF）だけだが、差分ペインでは全行が削除と追加の同じ文字列として並び、何が変わったのか読み取れなかった。git は CRLF の行を末尾に CR を付けたまま出力するが、サーバが差分の本文から CR を落としていた（作業ツリーは Rust の `str::lines`、コミットは明示的な `trim`）。また、コミット側の行数は gix の比較用パイプラインで数えており、改行だけの変更を「+0 −0」としていた。

## Decision

- **サーバは差分の本文から CR を落とさない。** 作業ツリーもコミットも、git が出すとおり行末の CR を残してクライアントへ渡す。
- **クライアントは CR を本文から外し、行の属性として持つ。** 行のコピーやパーマリンクの対象になる本文には CR を含めない。対になった削除行と追加行で行末だけが違うときに限り、両側の行末に改行コードの印（`␍␊` か `␊`）を強調付きで描く。対のない行と文脈行には印を出さない（CRLF の新規ファイルの全行に印が並ばないように）。
- **ファイル単位で「改行コードのみ」と名指す。** サーバがファイルごとに `eol_only` を返し、ファイル一覧にラベルを出す。作業ツリーは `git diff --numstat --ignore-cr-at-eol` から消えるファイル、コミットは行末の CR を除けば同一になる blob の組で判定する。差分の見出しには、本文から求めた変換の向き（`LF → CRLF` など）を出す。
- **コミット側の行数は生の blob から数える。** 差分の本文と同じ入力（gix-imara-diff の行単位比較）を使い、改行だけが変わった行も変更として数える。`git diff` の数え方と一致する。

## Consequences

- 改行コードの一括変換は、ファイル一覧のラベルで中身を開かずに見分けられる。
- コミットの行数が、CRLF を含むファイルで従来と変わりうる（改行だけの変更行が数に入る）。表示される差分の本文とは一致するようになる。
- コミットの行数を数えるために、変更のあったファイルの blob を毎回読む。gix の比較用パイプライン経由でも blob は読んでいたので、読み込み量はほぼ変わらない。
- `core.autocrlf` の設定差そのもの（WSL 側で全ファイルが変更扱いになること）は解消しない。それは利用者の git 設定か、リポジトリの `.gitattributes` で扱う。
