# ADR 0031: 片方の言語だけの言い回しの修正はコミットの印で日英同時更新の対象から外す

## Status

Accepted (2026-10-05)

## Context

日英の対になる文書（`X.jp.md` と `X.md`）は、片方を変えたらもう片方も同じ push で変えることを CI で確かめている（`.github/scripts/check-docs-tandem.sh`）。日本語が正なので、日本語で言ったことを英語が追い損ねるのを防ぐためのものだ。改行を入れ直しただけの変更は、もう一方が追うべき中身がないので対象外にしてある。

日本語の文書を校正すると、言い回しは変わるが言っていることは変わらない修正が多く出る。直訳調の比喩を普通の言葉にする、ダッシュやコロンを句点にする、主語と述語をかみ合わせる、といった修正である。英語版には直すところがないのに、チェックは英語版の変更を求める。英語版に意味のない変更を入れて通すのは、チェックの目的に反する。

## Decision

- **コミットメッセージに `[wording-only]` を含むコミットだけで変わったファイルは、日英同時更新の対象から外す。** 判定はファイルごとに行い、検査範囲でそのファイルに触れたコミットがすべて印付きのときだけ外す。印の無いコミットが 1 つでも触れていれば、従来どおり相手の言語の変更を求める。
- **印は日英どちらの側にも使える。** 英語版だけの言い回しの修正も同じ扱いにする。
- **変える側を名指す印として `[jp-only]` と `[en-only]` も使える。** `[jp-only]` は `.jp.md` の変更だけを、`[en-only]` は英語の `.md` の変更だけを対象外にする。印と違う側のファイルは対象外にならないので、付け間違いで相手の言語の変更を見逃すことがない。同じファイルに触れたコミットが、それぞれそのファイルに当てはまる印を持っていれば、印の種類が違っても対象外にする。
- **印を付けるのは、もう一方の言語が追うべき中身が無いときに限る。** 意味が明確になり、相手の言語にも反映すべき点が出た修正は、印を付けずに両方を変える。
- チェックの振る舞いの例を `.github/scripts/test-docs-tandem.sh` に置き、CI で実行する。

## Consequences

- 日本語の校正を、英語版に手を入れずに取り込める。
- 印を付けるかどうかは書き手の判断に任され、CI はその判断を確かめられない。意味の変わる修正に誤って印を付けると、英語版の追従漏れを見逃す。印付きのコミットはレビューで「本当に言い回しだけか」を見る。
- 言い回しの修正と意味の修正は別のコミットに分けることになる。
