# ADR 0026: 専用ウィンドウはブラウザの app mode で開き、ネイティブGUIは採らない

## Status

Accepted (2026-07-30)

## Context

ブラウザのタブ列に混ざらない専用ウィンドウで開きたいという要求に対し、実現手段は3つある。ネイティブ WebView（Tauri 等）を同梱する、 PWA としてインストールさせる、Chromium 系ブラウザの app mode （`--app=<url>`）で起動する。ADR 0001 が配布形態として「単一バイナリ・ C ツールチェーン非依存」を選んでいるため、手段の選択はその制約と衝突しうる。

## Decision

- **`--app` で Chromium 系ブラウザを `--app=<url>` 起動する。**得たいものはウィンドウの体裁だけであり、これはブラウザが既に持つ機能で満たせる。新規の依存もビルド手順の変更も伴わない。
- **ネイティブ WebView は採らない。** WebKitGTK のようなシステム C ライブラリ依存が復活し、ADR 0001 の配布形態の前提が崩れる。 crates.io 経由の `cargo install` が追加のシステムパッケージを要求し、 Termux 向けビルドは成立しなくなる。一方で得られる差分はウィンドウ枠のみで、ネイティブファイルダイアログは `rfd` で既にあり、現構成のままでは localhost のポートも残る。
- **PWA も採らない。** gitreant は CLI 起点であり、サーバ起動→ウィンドウ表示の順序が保証される必要がある。インストール済みアイコンからの起動はサーバ不在で白画面になる。加えてオリジンがポート単位なので `--port` を変えると別アプリ扱いになる。
- **通常のブラウザプロファイルを共有する。** `--user-data-dir` は渡さない。gitreant は認証を持たないためプロファイル分離の利得がなく、分離すればキャッシュ数十MBの置き場を管理する責任を負う。
- **Chromium 系が見つからなければ通常のブラウザ起動に落ちる。** ADR 0007 / 0013 と同じ degradation rule。警告は出さない。 `--no-open` が指定されていれば `--app` より優先し、何も開かない。
- **探索は「既知の場所を優先順に見て最初に存在したもの」。**ブラウザの優先順（Chrome → Edge → Brave → Chromium）をディレクトリの優先順より上位に置く。Windows は Chromium 系が PATH ではなく App Paths に登録されるため標準インストールルートを直接見る。macOS は app bundle 内の実行ファイルを叩く（`open -a` は Chromium のフラグを引数として渡せない）。それ以外の unix は PATH を走査する。

## Consequences

- Firefox のみの環境と Termux では `--app` は何も変えない。候補が空になり、通常のブラウザ起動と同じ経路を通る。
- 既存のブラウザが起動中なら、そのプロセスが app ウィンドウを開く。プロファイル共有の帰結であり、起動は速い。
- 起動コマンドの組み立て（候補の展開順・`--app` 引数の形）は純関数として単体テストできる。実際にウィンドウが出るかはマシンにブラウザが入っているかに依存するため、テストの対象にしない。
- ADR 0010 が定めた「いつ開くか」（転送時は開かない）は変わらない。本 ADR は「何を開くか」だけを決める。
