# ADR 0086: 行数のグラフとカレンダーは、1 つのブランチのコミットを数える

## Status

Accepted (2026-11-17)。[ADR 0043](0043-cumulative-chart.jp.md) と [ADR 0050](0050-calendar.jp.md) を改める。

## Context

行数のグラフ（[ADR 0043](0043-cumulative-chart.jp.md)）は、HEAD から最初の親をたどった連なりを、マージも含め、各コミットを最初の親と比べて足し上げていた。カレンダー（[ADR 0050](0050-calendar.jp.md)）は、読み込んだコミットのうちマージ以外を、ブランチを問わず数えていた。

git-flow のように `develop` を release のマージで `main` に入れるリポジトリでは、`main` の最初の親の連なりはほとんどがそのマージになる。マージはそれぞれ、その release のすべての行を数えた。そのためグラフは少数の巨大なロウソク足を描き、その間は平らだった。一方、すぐ下のカレンダーは、ほとんどの日に作業を示していた。2 つは別のコミットを数えていた。

## Decision

- **どちらも、1 つのブランチの作業を数える。** 数えるのは、読み込んだコミットのうちブランチの先頭から辿れるもので、マージ、stash の項目、未コミットの行は除く。それぞれ最初の親と比べる。マージが持ち込む変更は、元のコミットがすでに数えている。グラフはそれをコミットの時刻に沿って足し上げる。
- **ペインのヘッダーの一覧でブランチを選ぶ。** 一覧は、グラフかカレンダーを開いているあいだ出す。選べるのは、そのブランチ名を添えた HEAD、すべてのブランチ、ローカルのブランチとリモート追跡ブランチの名前である（ローカルが先）。既定は HEAD で、チェックアウトに従う。選んだブランチがなくなったら HEAD に戻る。

| 別の案 | 採らない理由 |
|---|---|
| 選べないまま HEAD の作業を数える | `develop` や feature ブランチだけを見る方法がない |
| 複数のブランチにチェックを付ける | 操作が重く、いくつかのブランチの和は、すべてのブランチとあまり変わらない |

## Consequences

- 履歴の大半がマージのブランチでも、グラフはマージのたびではなく、コミットが作られたところで上がる。
- 2 つのブランチに cherry-pick した変更は、すべてのブランチを選ぶと 2 回数える。
- 辿るのは、これまでどおり読み込み済みのコミットだけである（[ADR 0023](0023-progressive-loading.jp.md)）。
- テストでは、ブランチが数えるコミット、その足し上げ、一覧がグラフとカレンダーの両方を切り替えることを確かめる。
