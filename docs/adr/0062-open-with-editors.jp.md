# ADR 0062: 利用者が持つ一覧のエディタでファイルを開く

## Status

Accepted (2026-10-29)

## Context

変更されたファイルのメニューには「エディタで開く」があり、ファイルを OS の既定のアプリに渡していた。エディタを複数使い分けている人や、ファイルの種類の既定がエディタでない人は、使うエディタを選べなかった。実行するプログラムを選ぶのは、利用者のマシンでコマンドを動かすことである。サーバはすでにループバックの自分のページにしか応えない（[ADR 0038](0038-loopback-request-guard.jp.md)）。それでも、リクエストがプログラムと引数を名指しするなら、ページに届くものは何でも、名指ししたものを動かせてしまう。

## Decision

- **エディタの一覧はサーバ側に置く。** サーバの設定ファイル `config.toml` に、各エディタの名前、プログラム、引数を `[[editors]]` の表として書く。ファイルは、どの OS でも XDG のベースディレクトリが設定を置く場所に置く。`$XDG_CONFIG_HOME/gitreant`、なければホームディレクトリの `.config/gitreant` とし、`GITREANT_CONFIG_DIR` で上書きできる。一覧を保存するときは自分の表だけを書き換え、ファイルのほかのキーは残す。
- **設定ダイアログで編集する。** 設定のグループにエディタを名前、プログラム、引数とともに並べ、行を足したり消したりして、一覧をサーバに保存する。サーバがファイルに書く。
- **開くときはプログラムではなくエディタを名指しする。** ファイルのメニューに、各エディタの名前を付けた「〜で開く」を出す。リクエストは一覧の何番目のエディタかだけを送り、サーバがそのエディタのプログラムを引数とともに動かす。引数の `{path}` はファイルの絶対パスに、`{line}` は行番号に置き換え、行番号がなければ 1 とする。プログラムはシェルを通さずに直接動かすので、パスでコマンドを足すことはできない。パスは、既定のアプリで開くときと同じく、リポジトリの中にとどまらなければならない。
- **Windows では「プログラムから開く…」でシステムに尋ねる。** Windows のメニューには、システム自身のアプリ選択も出す。macOS と Linux には呼び出せる選択の画面がないので、一覧だけを出す。

## Consequences

- 一覧の読み書き、引数の置き換え、リポジトリの外のパスを拒むことは単体テストで確かめる。E2E テストで、設定から一覧を保存し、その一覧のエディタでファイルを開く。
