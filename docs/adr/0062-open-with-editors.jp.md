# ADR 0062: 利用者が持つ一覧のエディタでファイルを開く

## Status

Accepted (2026-10-29)

## Context

変更されたファイルのメニューには「エディタで開く」があり、ファイルを OS の既定のアプリに渡していた。エディタを複数使い分けている人や、ファイルの種類の既定がエディタでない人は、使うエディタを選べなかった。実行するプログラムを選ぶのは、利用者のマシンでコマンドを動かすことである。サーバはループバックの名前宛てのリクエストだけに応え、ページからのリクエストは自分のページのものだけに応える（[ADR 0038](0038-loopback-request-guard.jp.md)）。ただし、ブラウザ以外のプログラムが送るような、`Origin` をまったく持たないリクエストは受け付ける。ほかのアカウントと共有するマシンでは、そうしたプログラムがポートに届く。リクエストがプログラムと引数を名指しできるなら、ポートに届くものは何でも、名指ししたものをサーバの利用者として動かせてしまう。

## Decision

- **エディタの一覧はサーバの設定ファイルに置く。** `config.toml` に、各エディタの名前、プログラム、引数を `[[editors]]` の表として書く。ファイルは、どの OS でも XDG のベースディレクトリが設定を置く場所に置く。`$XDG_CONFIG_HOME/gitreant`、なければホームディレクトリの `.config/gitreant` とし、`GITREANT_CONFIG_DIR` で上書きできる。
- **書くのは CLI と利用者の手だけとする。** `gitreant editor add`、`remove`、`list` が表を編集し、ファイルのほかのキーは残す。ファイルを手で編集してもよい。サーバは読むだけで、一覧を書くリクエストはない。設定ダイアログは、エディタ、ファイルのパス、エディタを足すコマンドを示す。
- **開くときはプログラムではなくエディタを名指しする。** ファイルのメニューに、各エディタの名前を付けた「〜で開く」を出す。リクエストは一覧の何番目のエディタかだけを送り、サーバがそのエディタのプログラムを引数とともに動かす。引数の `{path}` はファイルの絶対パスに、`{line}` は行番号に置き換え、行番号がなければ 1 とする。`{path}` がなければパスを最後に足す。置き換えは 1 つの引数の中で行い、プログラムはシェルを通さずに直接動かすので、パスで引数やコマンドを足すことはできない。パスは、既定のアプリで開くときと同じくリポジトリの中にとどまらなければならず、絶対パスなのでオプションとして読まれることもない。プログラムは切り離して動かし、サーバの入出力を渡さない。
- **信頼するもの。** ファイルにあるプログラムと引数は利用者自身のものであり、シェルの設定と同じく信頼する。リクエストが名指しするファイルは信頼しない。クローンしたリポジトリのファイルは誰のものでもありうるからである。開くファイルを実行する「エディタ」、たとえばインタプリタは、リポジトリにあるものを動かす。
- **Windows では「プログラムから開く…」でシステムに尋ねる。** Windows のメニューには、システム自身のアプリ選択も出す。これは利用者が選ぶまで何も動かさない。macOS と Linux には呼び出せる選択の画面がないので、一覧だけを出す。
- **Windows ではスクリプトを拡張子付きで書く。** プログラムは Rust の標準ライブラリと同じく探し、付け足す拡張子は `.exe` だけなので、VS Code のようなバッチの起動スクリプトは `code.cmd` と書く。

## Consequences

- 一覧の読み書き、引数の置き換え、リポジトリの外のパスを拒むことは単体テストで確かめる。CLI は通しで確かめ、E2E テストで、ページが一覧を書けないことと、一覧のエディタでファイルを開くことを確かめる。
- サーバ自身のページと CLI だけが持つ秘密をリクエストが運ぶようになるまでは、マシン上のどのプログラムも、既定のアプリで開くことを頼めるのと同じく、リポジトリのファイルを一覧のエディタで開くことを頼める。
