# ADR 0077: Windows ではサーバの記録に専用のアクセス権を付ける

## Status

Accepted (2026-11-02)。[ADR 0063](0063-request-token.jp.md) を改める。

## Context

サーバの記録はそれぞれ秘密を持ち（[ADR 0063](0063-request-token.jp.md)）、CLI はそれを読んでサーバとやり取りする。Unix では、記録のディレクトリをモード 0700 で、記録を 0600 で作る。Windows では何も設定していなかった。記録は `%LOCALAPPDATA%` の下にあり、ユーザーのプロファイルの中のディレクトリは本人だけのものと見なしていた。

いつもそうとは限らない。2026-11-02 に、サンドボックスを入れたマシンで、`%LOCALAPPDATA%` がそのサンドボックスのグループに読み取りを許しており、それが記録のディレクトリと動いているサーバの記録に継承されていた。そのグループには、管理者でないアカウントが 2 つ入っていた。[ADR 0071](0071-other-accounts-in-scope.jp.md) はこうしたアカウントを範囲内とする。秘密があれば、それらは API をすべて使える。

## Decision

- **Windows では、記録のディレクトリに専用のアクセス権を付ける。** gitreant はそれを作るときに、何も継承しないアクセス権を設定する。許すのは、今のユーザー、SYSTEM、Administrators だけで、ディレクトリとその中に作られるものすべてに及ぶ。すでにある記録や起動用ファイルにも及ぶ。

## Consequences

- ほかのアカウントが記録やその横の起動用ファイルを読めるのは、プロファイルのディレクトリが何を許していても、管理者のときだけになる。
- この変更より前に起動したサーバの記録は、サーバがそのディレクトリにもう一度書き込むまで、古いアクセス権のままである。
- `GITREANT_STATE_DIR` にも同じアクセス権を付ける。
- テストで、アクセス権をシステムから読み戻し、ディレクトリが継承を断っていること、ディレクトリと記録が許すのはユーザー、SYSTEM、Administrators だけであることを確かめる。
