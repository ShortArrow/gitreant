# ADR 0077: Windows ではサーバの記録に専用のアクセス権を付ける

## Status

Accepted (2026-11-02)。[ADR 0039](0039-server-records.jp.md) と [ADR 0063](0063-request-token.jp.md) を改める。

## Context

サーバの記録はそれぞれ秘密を持ち（[ADR 0063](0063-request-token.jp.md)）、CLI はそれを読んでサーバとやり取りする。Unix では、記録のディレクトリをモード 0700 で、記録を 0600 で作る。Windows では何も設定していなかった。記録は `%LOCALAPPDATA%` の下にあり、ユーザーのプロファイルの中のディレクトリは本人だけのものと見なしていた。

いつもそうとは限らない。2026-11-02 に、サンドボックスを入れたマシンで、`%LOCALAPPDATA%` がそのサンドボックスのグループに読み取りを許しており、それが記録のディレクトリと動いているサーバの記録に継承されていた。そのグループには、管理者でないアカウントが 2 つ入っていた。[ADR 0071](0071-other-accounts-in-scope.jp.md) はこうしたアカウントを範囲内とする。秘密があれば、それらは API をすべて使える。

## Decision

- **Windows では、記録のディレクトリに専用のアクセス権を付ける。** gitreant はそこに書き込むたびに、何も継承しないアクセス権を設定する。許すのは、今のユーザー、SYSTEM、Administrators だけで、ディレクトリとその中に作られるものすべてに及ぶ。gitreant が以前にそこへ書いた記録や起動用ファイルにも及ぶ。
- **`GITREANT_STATE_DIR` は、記録を置くディレクトリの親を指す。** 記録は、既定の状態のディレクトリの下の `gitreant/servers` と同じく、その `servers` サブディレクトリに置く。こうして、アクセス権を設定するのは常に gitreant 専用のディレクトリだけになる。

## Consequences

- ほかのアカウントが記録や同じディレクトリに書いた起動用ファイルを読めるのは、プロファイルのディレクトリが何を許していても、管理者のときだけになる。
- この変更より前に起動したサーバの記録は、サーバがそのディレクトリにもう一度書き込むまで、古いアクセス権のままである。
- アクセス権を持たないドライブのように、アクセス権を設定できないところでは、記録を書かず、サーバは自分を記録できなかったと伝える。
- テストで、親ディレクトリをすべてのユーザーが読めるようにしてからその下に記録を書き、アクセス権をシステムから読み戻して、ディレクトリが継承を断っていること、ディレクトリと記録が許すのはユーザー、SYSTEM、Administrators だけであることを確かめる。
