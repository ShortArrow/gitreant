# ADR 0083: リンクに入れた札でページを 1 回だけ開く

## Status

Accepted (2026-11-16)。[ADR 0063](0063-request-token.jp.md) を改める。

## Context

ページにはサーバの秘密が要る（[ADR 0063](0063-request-token.jp.md)）。`gitreant` と `gitreant open` は、秘密を POST する起動用ファイルを通して渡す。`--no-launcher` のときと Android では、開くアドレスのフラグメントに入れて渡す（[ADR 0076](0076-post-the-secret.jp.md)）。どちらも、ブラウザを自分で開く。

利用者にリンクを見せるだけのプログラムは、どちらも使えない。ほかのプログラムの端末や、マシンでの作業をまとめるセッションがこれにあたる。`http://127.0.0.1:<port>/` へのリンクでは、秘密のないページが開く。秘密を入れたリンクは、秘密を画面、クリップボード、端末のスクロールバック、リンクを渡されたブラウザのコマンドラインに置く。サーバが動いているあいだ、秘密はそこに残る。[ADR 0072](0072-no-browser-showing-the-secret.jp.md) と ADR 0076 は、そういう場所に秘密を置かないようにしている。

## Decision

- **`gitreant open --ticket` は札を入れたリンクを表示する。** `gitreant open` と同じく、動いているサーバに秘密を持つことを示させる（[ADR 0075](0075-prove-before-opening.jp.md)）。そのあとサーバに札を求め、`http://127.0.0.1:<port>/#ticket=<ticket>` を表示する。ブラウザは開かない。
- **サーバは秘密を持つ相手にだけ札を出す。** `POST /api/tickets` は、ほかの API のリクエストと同じく秘密を持つ。札は OS の暗号用の乱数源から取った 32 バイトで、16 進で表す。サーバは札を、出した時刻とともにメモリにだけ置く。サーバの記録にもコマンドのログにも書かない。
- **札は 60 秒以内に 1 回だけ秘密と引き換えられる。** `POST /api/tickets/redeem` は秘密を求めない。それでも [ADR 0038](0038-loopback-request-guard.jp.md) のリクエストの検査は通る必要がある。ループバックの名前宛てであること、そしてページ自身のオリジンから来たか、ページでないクライアントのように `Origin` を持たないことである。札が 60 秒以内に出されたもので、まだ引き換えられていなければ、サーバは秘密を返す。この応答はキャッシュさせない。札は引き換えた時点で消すので、同じ札での次の試みは失敗する。使い済み、期限切れ、出していない札には 403 を返し、秘密は何も返さない。札の比較は一定時間で行い、期限切れの札は次の札を出すときに捨てる。
- **札はフラグメントに置く。** フラグメントはサーバに届かない。そのため札は、リクエストの行にもアクセスログにも `Referer` にも載らない。ページは、引き換える前に札をアドレスとセッションの履歴から消す。引き換えた秘密は、ほかの方法で渡された秘密と同じく、自分のタブのために持つ。札を拒まれたページは秘密を持たず、`gitreant open` を示す。

| 別の案 | 採らない理由 |
|---|---|
| 秘密を入れたリンク | サーバが動いているあいだ、リンクが渡った場所すべてに秘密が残る |
| 起動用ファイルへの `file:` リンク | 起動用ファイルを書ける環境にしかなく、WSL では使えない。リンクを表示する端末や遠隔の画面が、`file:` リンクを開けないことがある |
| サーバが止まるまで使える札 | 後からコピーしたり読んだりしたリンクでも、ページが開いてしまう |

## Consequences

- 札の価値は秘密と同じである。ただし、それは引き換えられるか 60 秒たつまでで、秘密はサーバが止まるまで続く。その間に、画面、クリップボード、スクロールバック、リンクを表示したプログラムのログからリンクを読み、先に引き換えた者は秘密を得る。そのとき利用者のページは拒まれ、`gitreant open` を示す。ほかの者が札を引き換えたことを示すのは、この拒否だけである。
- 端末でクリックしたリンクは、たいていブラウザのコマンドラインで渡される。Linux と macOS では、ほかのアカウントがそこを読み（[ADR 0071](0071-other-accounts-in-scope.jp.md)）、ブラウザより先に札を引き換えられる。これは `--no-launcher` と同じ露出を、60 秒以内の 1 回の引き換えに狭めたものである。`--no-launcher` と同じく、札を表示するのは利用者の選択である。
- ほかのアカウントがポートに残した service worker やキャッシュされたページは、フラグメントを読んで札を引き換えられる。秘密については、[ADR 0073](0073-page-under-a-path-of-each-start.jp.md) と [ADR 0079](0079-accept-the-cache-with-the-service-worker.jp.md) がこの場合を受け入れている。
- リンクは `127.0.0.1` を指すので、サーバが動くマシンのブラウザでしかページを開けない。
- テストでは、札が 1 回だけ引き換えられること、期限切れの札、出していない札、秘密なしで札を求めることを確かめる。動いているサーバでの引き換えとその応答をキャッシュさせないことも確かめる。ページについては、引き換える前に札をアドレスから消すこと、引き換えを拒まれたら秘密なしで開くことを確かめる。リンクのアドレスも確かめる。札なしで開いたページは、これまでどおりに動く。
