# ADR 0080: 転送するときにサーバに秘密を示させるのは 1 回にする

## Status

Accepted (2026-11-03)。[ADR 0075](0075-prove-before-opening.jp.md) を置き換える。

## Context

`gitreant` は、動いているサーバにリポジトリを転送するとき、サーバが記録の秘密を持つことを示させ（[ADR 0064](0064-prove-the-secret.jp.md)）、各リポジトリの追加を頼み、ページを開く。ADR 0075 は、リポジトリを追加している間にサーバが終了し、その間にほかのアカウントがポートを取る場合に備えて、ページを開く直前の 2 回目の証明を加えた。

2 回目の証明は、この隙を短くするが、なくしはしない。ブラウザが接続するときにポートを持つ相手に届くからである。この隙でそのアカウントが得るのは、終了したサーバの秘密と、ユーザーのブラウザで開かれる自分のページである。その秘密では何も開けない。そのページは service worker かキャッシュされた応答を残せる。[ADR 0073](0073-page-under-a-path-of-each-start.jp.md) と [ADR 0079](0079-accept-the-cache-with-the-service-worker.jp.md) は、ブラウザが古いタブ、ブックマーク、履歴からそうしたページを開いた場合について、どちらも受け入れている。

## Decision

- **CLI がサーバに秘密を示させるのは、何かを送る前の 1 回とする。** ページのアドレスを表示する前や開く前に、もう一度は示させない。

## Consequences

- 隙は、証明からブラウザが接続するまでで、サーバがリポジトリを開く時間を含む。この隙にポートを取ったアカウントのページは開かれ、CLI はエラーを出さない。この経路は、ADR 0073 が受け入れるものに加わる。
- 最初の証明に失敗すれば何も送らないことは変わらない。これは `tests/impostor.rs` で確かめる。
