# ADR 0076: 秘密は POST で渡し、アドレスは固定する

## Status

Accepted (2026-11-02)。[ADR 0063](0063-request-token.jp.md)、[ADR 0072](0072-no-browser-showing-the-secret.jp.md)、[ADR 0073](0073-page-under-a-path-of-each-start.jp.md) を改める。

## Context

ページは `http://127.0.0.1:<port>/<path>/#token=<secret>` で開いていた。パスは起動ごとに新しくしていた（[ADR 0073](0073-page-under-a-path-of-each-start.jp.md)）。アドレスが起動のたびに変わるのでブックマークできず、人が読んでも正しいアドレスかどうか見分けられなかった。秘密はアドレスに入っていた。つまり、アドレスバーにも履歴にも残り、アドレスをそのままブラウザに渡すところではブラウザのコマンドラインにも出た。

`POST` で送ったフォームに、ブラウザはキャッシュで答えない。そのため、`POST` による遷移は、ほかのプログラムが同じアドレスにキャッシュさせた応答があってもサーバに届く。2026-11-02 に、ストレージの区切りを有効にした Chromium で、`http://127.0.0.1:<port>/` へフォームを送る起動用ファイルは、そこに 1 年キャッシュされたページを越えてサーバに届いた。続いてページは `history.replaceState` でアドレスを `/` にし、そのあとの再読み込みは何も問わず `GET` で `/` を取得した。ポートに残された service worker は、それまでフラグメントを読んだのと同じく、`POST` にも応え、本文の秘密を読んだ。

## Decision

- **ページは `/` に置く。** `gitreant` と `gitreant list` が表示するアドレスは、起動ごとに変わらず秘密を含まない `http://127.0.0.1:<port>/` とする。
- **起動用ファイルが秘密を POST する。** 起動用ファイルを書けるところでは、Windows を含め、ブラウザは秘密を `POST` で `/` に送るフォームを持つファイルを開く。サーバは、秘密が一致する `/` への `POST` に、秘密を書き込んだページで答える。その応答はキャッシュさせず、オリジンのキャッシュを消す。秘密が一致しないものにはページを返さない。ページは秘密を自分から取り除き、自分のタブのために持ち、アドレスを `/` にする。
- **ページは自分のファイルを、この起動のパスから読む。** ページの HTML は `/<value>/` を base に指定する。値は起動ごとに新しいので、スクリプトやスタイルは、以前にポートを持ったプログラムがキャッシュさせられなかったアドレスに問い合わせる。ページ自身のアドレスは `/` のままである。
- **`/` への `POST` は、どのオリジンからでもリクエストの検査を通す。** 起動用ファイルのオリジンは `null` なので、状態の変更についての [ADR 0038](0038-loopback-request-guard.jp.md) の検査は当てはめない。宛先の名前の検査はそのまま当てはめ、本文の秘密がオリジンの代わりになる。
- **アドレスを渡すのは、起動用ファイルを使えないところだけにする。** `--no-launcher` を付けたときと、ブラウザが起動用ファイルを読めない Android では、ブラウザに `http://127.0.0.1:<port>/?<value>#token=<secret>` を渡す。クエリは起動ごとに新しく、ほかのプログラムがキャッシュさせた応答を避ける。WSL と、起動用ファイルを書けないときは、[ADR 0072](0072-no-browser-showing-the-secret.jp.md) のとおりブラウザを開かない。
- **`gitreant open` でページを開き直す。** 動いているサーバに秘密を示させ、同じ方法でページを開き、リポジトリは足さない。秘密なしで開いたページは、このコマンドを示す。

## Consequences

- アドレスは起動ごとに変わらず秘密を含まないので、人が一目で確かめられる。手でそこを開いたタブは秘密を持たず、`gitreant open` を示す。
- Windows でも、ブラウザのコマンドラインに秘密が出なくなる。
- 再読み込みや、手で `/` を開くことは、`GET` でサーバにページを問い合わせる。そのページがほかのプログラムのキャッシュさせた応答を避けられるのは、`Clear-Site-Data: "cache"` でキャッシュを消すブラウザだけである。スクリプトやスタイルは、ページをサーバが答える限り、どこでも避けられる。
- gitreant が動いていないときに手で `/` を開くことは、ほかのアカウントのページがブラウザに届く経路でもある。これは ADR 0073 が受け入れた場合である。
- ポートに残された service worker は、ADR 0073 が受け入れたとおり、秘密を読める。
- 起動用ファイルのフォーム、`/` への `POST` に対する検査の例外、秘密が一致するときと一致しないときの base を含む応答、ページによる秘密の読み取りと取り除き、`gitreant open` を、それぞれテストで確かめる。
