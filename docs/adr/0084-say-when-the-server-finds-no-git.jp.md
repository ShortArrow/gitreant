# ADR 0084: サーバが git を見つけられないときは、そう示す

## Status

Accepted (2026-11-17)

## Context

gitreant はグラフを gix でプロセスの中で読む。一方、署名の確認（[ADR 0037](0037-deferred-signature-check.jp.md)）と行数の集計（[ADR 0041](0041-diff-stats-per-commit.jp.md)）は、PATH で見つけた `git` を動かして行う。そのため、PATH に使える `git` がないサーバでも、グラフはすべて表示される。

2026-11-17 に、Windows 11 で予定タスクから起動した gitreant 0.4.0 のサーバは、PATH に `%ProgramFiles%\Git\cmd` を展開しないまま持っていた。Windows はプログラムを探すときに PATH の項目を展開しないので、サーバは `git` を見つけられなかった。コマンドのログでは、署名の確認も行数の集計も、すべて「program not found」で失敗していた。ページは署名付きのコミットを「Signed」と、行数のグラフを「29 commits still being counted」と表示し、どちらも変わらなかった。同じマシンの SSH のシェルは PATH が展開されており、同じコマンドで署名は正しいと出た。

## Decision

- **サーバは、`git` が応えるかを 1 回だけ調べる。** PATH から `git --version` を動かして調べる。gpg が応えるかは、これまでどおりそのあとで調べる。
- **`git` がなければ、読み込みは確認する署名も数えるコミットも残さない。** 区切りのたびに失敗させるのではなく、どちらも動かさない。
- **view がそのことを示す。** view は `git_missing: true` を持つ。ページは、サーバが git を見つけられないので、署名を確認せず、行数も数えていないことを示す。署名付きのコミットのバッジは、その理由でサーバが確認できないと示す。行数のグラフとカレンダーは「数えています」ではなく、行数を数えていないと示す。
- **gitreant は PATH の `%…%` を展開しない。** サーバは、Windows が起動するほかのプログラムと同じく、PATH が名指すものを動かす。`git` を展開しないまま名指す PATH は、サーバを起動する側で直す。
- **gpg がないときは変えない。** そのときは QUALITY のとおり、署名があることだけを示す。

## Consequences

- `git` を見つけられない PATH で起動したサーバは、ページと Info ダイアログで、まだ数えているサーバと見分けられる。
- あとで `git` を使えるようにしても、動いているサーバの状態は変わらない。調べるのは 1 回だけで、再起動すれば変わる。
- `gitreant doctor` は、自分が動くシェルの PATH を調べる。そのため、サーバが見つけられない `git` を見つけることがある。
- テストでは、見つかった道具の組み合わせごとの状態、`git` なしの読み込みが何も残さずに理由を示すこと、バッジの文言、`git` がないと示す view に対するページの知らせとグラフの文言を確かめる。
