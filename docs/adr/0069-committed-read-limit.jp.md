# ADR 0069: コミットのファイルも作業ツリーと同じ大きさの上限で読む

## Status

Accepted (2026-10-31)。[ADR 0061](0061-diff-context.jp.md) を改める。

## Context

ADR 0061 は、サーバが差分の新しい側のファイルを読み、未コミットの変更なら作業ツリーを「未追跡のファイルと同じ大きさの上限で」読むと決めた。その上限は 4 MiB で、これより大きい未追跡のファイルは読まない。そのため、紛れ込んだ VM イメージやデータセットが、メモリにも応答にも入らない。コミットのツリーを読む側には上限がなかった。コミットの差分で隠れた行を開くと、ファイルの blob を大きさにかかわらず丸ごと読み、丸ごと返していた。そのため、履歴の中の大きなファイルは、作業ツリーなら入らないはずのメモリと応答に入っていた。

git はオブジェクトの大きさをそのヘッダーに持っており、オブジェクトを読まずにヘッダーだけを読める。

## Decision

- **コミットのツリーのファイルは、blob が 4 MiB 以下のときだけ読む。** これは作業ツリーと同じ上限である。先に blob の大きさをヘッダーから読み、それより大きい blob は、ディスク上の大きすぎるファイルと同じく何も返さない。
- コミットの差分は変えない。差分を取るために、これまでどおり両側を丸ごと読む。

## Consequences

- 4 MiB を超えるコミットのファイルは、差分ペインで変わらない行が隠れたままになり、ペインは読めないことを示す。作業ツリーの同じ大きさのファイルと同じ扱いである。
- アダプタのテストは、ちょうど 4 MiB のコミットのファイルを読んでその内容が返ることを確かめ、1 バイト大きいファイルを読んで何も返らないことを確かめる。
