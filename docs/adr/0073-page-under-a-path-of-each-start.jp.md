# ADR 0073: ページを起動ごとのパスの下で開き、ページが動かし続けるものは受け入れる

## Status

Accepted (2026-11-01)。

## Context

ページは `http://127.0.0.1:<port>/#token=<secret>` で開いていた（[ADR 0063](0063-request-token.jp.md)）。ブラウザは、オリジンに残されたもの（キャッシュや service worker）を、そこを配るプログラムが替わっても持ち続ける。オリジンは、アドレスとポートだけで決まる。[ADR 0071](0071-other-accounts-in-scope.jp.md) が範囲内としたほかのアカウントは、gitreant が去ったポートを取り、そこでページを配れる。そのあいだにユーザーのブラウザがそのアドレスを開くと（古いタブ、ブックマーク、履歴から）、そのページは 1 年キャッシュされる応答や service worker を残せる。あとで gitreant が同じポートで起動してページを開くと、ブラウザはサーバに問い合わせずに残されたもので応え、仕込まれたスクリプトがアドレスやページのストレージから秘密を読む。そのプログラムがポートを持っていたあいだにユーザーが開いたままにしたページは、プログラムがポートを手放したあとも動き続け、本物のページがあとでオリジンのストレージに書くものを読む。

起動をまたいで保つオリジンは、どれも同じように汚染できる。ユーザーだけが知る `localhost` の下の名前でも同じで、ブラウザが開いた時点でポートを持つ相手に名前が伝わる。秘密の渡し方を変えても役に立たない。汚染されたページはそのオリジンのスクリプトとして動き、ページが受け取るものをすべて受け取る。起動ごとに新しい名前でページを開けば塞げるが、ページがブラウザのストレージに保つ設定（言語、テーマ、日付形式、パネル幅など）は 1 つのオリジンに属するので、起動のたびにすべて失われる。

1 つのオリジンの中では、2 つの方法は違う。キャッシュされた応答は自分のアドレスにだけ応え、サーバは `Clear-Site-Data: "cache"` でオリジンのキャッシュを消せる。このときページのストレージは残る。service worker は、サーバに問い合わせる前に、その下のすべてのアドレスに応える。消せるのは `Clear-Site-Data: "storage"` だけで、これは設定もすべて消す。2026-11-01 に、Chrome が出荷するとおりストレージの区切りを有効にした Chromium で、2 つの方法と 2 つのヘッダを試した。

## Decision

- **ページは、この起動のパスの下に置く。** ページは `/<path>/` で配り、パスは `HMAC-SHA256(secret, "page path")` の 16 進 32 桁である。起動のたびに新しく、起動前には知られておらず、秘密について何も明かさない。gitreant が開くアドレスと表示するアドレスはこのパスを含む。ほかのパスへのリクエストは、キャッシュされない `303` でこのパスへ送る。
- **ページはオリジンのキャッシュを消す。** ページの応答はキャッシュされず、`Clear-Site-Data: "cache"` を持つ。
- **ページは API をキャッシュを通さずに問い合わせる。** リクエストは `cache: "no-store"` で送る。
- **ページは秘密を自分のタブのために持つ。** 秘密は、オリジンのすべてのタブが読むオリジンのストレージではなく、タブのセッションストレージに置き、以前の版がそこに置いた秘密は捨てる。
- **ほかのアカウントのページが動かし続けるものは受け入れる。** service worker と、あとでページが読み込まれるタブへの参照を持つそのページのウィンドウで、後者は同一オリジンポリシーによりそのタブを読める。それが秘密を読むには、次のすべてが要る。
  - 管理者でないほかのアカウントが、gitreant の去ったポートを取っている。
  - そのあいだに、ユーザーのブラウザがそのアドレスを開く。
  - ブラウザがその worker を捨てる前に、gitreant が同じポートで起動し、そのブラウザでページが開かれる。または、そのウィンドウが参照を持つタブでページが開かれる。gitreant はそうしたタブを求めない。アドレスをシステムかブラウザに渡し、タブはそちらが選ぶ。

## Consequences

- ほかのプログラムがブラウザのキャッシュに残した応答は、gitreant から開いたページに届かない。`Clear-Site-Data: "cache"` でキャッシュを消すブラウザでは、`/` のブックマークにも届かない。
- ページの設定は起動をまたいで残る。秘密なしで開いたタブ（ブックマークや手入力から）は秘密を持たず、秘密付きで開く方法を示す。
- パスは秘密ではなく、接続した相手は `303` から知る。起動前に知られていなければ足りる。
- ほかのアカウントは、上で受け入れた場合を除き、秘密なしには何も得られない。ブラウザで `127.0.0.1` のサイトデータを消すと service worker が消え、そのページのウィンドウを閉じると残りも消える。
- パスの導き方とルーティングは単体テストで、`303`、ヘッダ、パスの下のページのファイルは動いているサーバに対して、ページのリクエストがキャッシュを通らないことと、秘密がオリジンのストレージに置かれないことはフロントエンドのテストで確かめる。
