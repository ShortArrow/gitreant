# ADR 0039: 動いているサーバを記録し、CLI から見つけられるようにする

## Status

Accepted (2026-10-22)

## Context

動いているサーバと話すコマンド（`--shutdown`、`restart`、`refresh`）は、どれもポートでサーバにたどり着き、ポートの既定は 4000 である。別のポートで起動したサーバは、そのポートをもう一度指定しないと止められず、どのサーバがどこで動いているかを一覧にする手段もない。CLI は、あるポートにいるのが gitreant かどうかは見分けられる（`GET /api/ping`）が、渡されていないポートを見つけることはできない。

## Decision

- **サーバごとの記録。** サーバは待ち受けを始めたら、ユーザーごとのディレクトリに `<port>.json`（ポート、pid、起動時刻、版）を書き、止まるときに消す。ディレクトリは、Windows では `%LOCALAPPDATA%\gitreant\servers`、macOS では `~/Library/Caches/gitreant/servers`、そのほかでは `$XDG_RUNTIME_DIR/gitreant/servers` とし、なければ `$XDG_STATE_HOME`、さらになければ `~/.local/state` を使う。テストのために、`GITREANT_STATE_DIR` でディレクトリを差し替えられる。
- **記録は手がかりにすぎない。** 記録が数に入るのは、そのポートが gitreant として応えている間だけである。応えない記録（落ちたか強制終了されたサーバが残したもの）は、見つけた時点で消す。サーバが表示しているリポジトリは記録せず、サーバに尋ねる。
- **`gitreant list`** は、動いている各サーバの URL、pid、起動時刻、版、リポジトリを表示し、なければそう表示する。
- **ポートは、渡されなければ探す。** `--port` のない `--shutdown`、`restart`、`refresh` は、動いている唯一のサーバを相手にする。1 つもなければこれまでどおり 4000 を使い、複数あれば一覧を表示して失敗し、`--port` を求める。`--shutdown --all` は、動いているすべてのサーバを止める。

## Consequences

- この版より前の版が起動したサーバは記録を書かないので、再起動するまで一覧にも出ず、見つけることもできない。
- サーバを起動するときは、これまでどおり `--port` か 4000 を使う。探すのは、動いているサーバと話すコマンドだけである。
- 記録の信頼性は置き場所のディレクトリと同じなので、ディレクトリはユーザーごとにする。記録があっても、gitreant として応えないポートに CLI が働きかけることはない。
