# ADR 0070: 作業ツリーの中にあるファイルだけを開く

## Status

Accepted (2026-10-31)。[ADR 0062](0062-open-with-editors.jp.md) を改める。

## Context

変更ファイルは、OS の既定のアプリか、ユーザーのエディタで開ける。ADR 0062 は「パスはリポジトリの中にとどまらなければならない」とし、リクエストが指すファイルは信頼しないとした。クローンしたリポジトリのファイルは誰のものでもありうるからである。ところが、両方の経路の検査はパスの文字列しか見ておらず、絶対パスと `..` を拒むだけだった。ディレクトリのリンクやジャンクションを通るパス、それ自体がリンクのファイル、`.git` の中へのパスは、どれも検査を通った。そのため、開くとリポジトリの外のファイル（たとえばホームディレクトリのファイル）や、リポジトリ自身の設定に届いた。既定のアプリが開くファイルは、それが実行するプログラムであることもある。

[ADR 0068](0068-read-only-changed-paths.jp.md) は、作業ツリーを読む前に同じことを確かめる。ただし、それ自体がリンクのファイルはリンク先の文字列として読むので、そのディレクトリだけを解決する。リンクを開くと、リンクの先が開く。

## Decision

- **ファイルは、そこにあって作業ツリーの中にあるときだけ開く。** パスの途中のディレクトリがリンクやジャンクションであってはならない。リンクも含めて解決した先は作業ツリーの下にあり、大文字小文字を問わず `.git` という名前の部分を持たず、リポジトリの git ディレクトリの外になければならない。これは ADR 0068 の検査に、リンクをたどることを加えたものである。検査を通らないパスは、`..` を含むパスと同じく、どのプログラムを使うかを決める前に拒む。
- リポジトリのフォルダそのものは、これまでどおりパスなしで開ける。

## Consequences

- 作業ツリーの中のファイルへのリンクは、そのファイルを開く。作業ツリーの外へのリンク、ジャンクションを通るパス、`.git` の下のファイル、もうディスクにないファイルは開かない。開けなかったときはいつもそうであるように、メニューは何も示さない。
- アダプタのテストは、作業ツリーの中のファイル、`.git/config`、`.GIT/config`、存在しないファイルを開こうとする。Linux と macOS では、作業ツリーの中へのリンク、外へのリンク、`.git/config` へのリンク、リンクしたディレクトリを通るパスも試す。Windows では、ジャンクションを通るパスを試す。サーバのテストは、リストにないエディタで `.git/config` を開くよう求め、エディタを探す前にパスが拒まれることを確かめる。
