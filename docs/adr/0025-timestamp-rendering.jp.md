# ADR 0025: 日時形式は単一のクライアント設定で全表示を統べ、絶対時刻をツールチップで常に残す

## Status

Accepted (2026-07-28)

## Context

日時はグラフ行の右端とコミット詳細ペインの2箇所に出るが、前者は固定幅の `YYYY-MM-DD HH:mm`、後者は `toLocaleString()` と実装がばらばらだった。表示形式をユーザーが選べるようにするにあたり、保存先（サーバの設定ファイルかクライアントか）と、形式ごとに情報量が落ちる問題をどう扱うかを決める必要がある。

## Decision

- **保存先は localStorage。** 表示形式は端末とブラウザの見た目の好みであり、リポジトリの状態でもセッションの状態でもない。サーバ側の設定ファイル（config.toml）やセッション永続化（session.json）は導入しない。
- **設定は1つで、日時を出す全箇所を統べる。** グラフ行とコミット詳細で別の形式が出る状態は、同じ情報が2つの見え方をするというバグに近い。`iso`（既定、固定幅 `YYYY-MM-DD HH:mm`）/ `locale`（選択中のUI言語のロケール表記）/ `relative`（`3 days ago`）の3値。
- **既定は `iso`。** 固定幅で桁が揃い、ブラウザのロケールに依存せず、年月日の順序が一意に読める。
- **どの形式でも `title` 属性に秒までの絶対時刻を出す。** `relative` は情報を落とす表示なので、正確な時刻を確かめる手段を必ず残す。これにより形式選択が「情報を捨てる選択」にならない。
- **相対表記は `Intl.RelativeTimeFormat` に委譲する。** 単位ごとの訳語を自前辞書（ADR 0019）に増やさない。基準時刻は引数で受け取り、整形関数を純関数に保つ。

## Consequences

- ログペインの時刻は対象外。ログの時刻はセッション中の時刻表示であり、日付を持たないため同じ軸に乗らない。
- `relative` は文字列幅が可変なので、グラフ行の時刻列は固定幅ではなくなる。桁揃えを重視する利用者には既定の `iso` がある。
- 形式の追加は整形関数の分岐と辞書のラベル追加で済む。
