# ADR 0006: ファイルdiffは1ファイルずつオンデマンドで取得する

## Status

Accepted (2026-07-10)

## Context

ADR 0005 はコミット詳細をファイル単位の統計までとし、「パッチ本文が必要になったら別エンドポイントで追加する」と決めた。コミット詳細のファイル名クリックでdiff本文を表示する要件が生じ、その別エンドポイントを設計する。

## Decision

- **`POST /api/diff` に `{repo, id, path}`** で1ファイル分だけ取得する。コミット全体のパッチを一括で返さないのは、大きなコミットで不要な blob diff を計算しないため（ユーザーが見るのは通常ごく一部のファイル）。
- diff は ADR 0005 と同じく**第1親との比較**。blob の取得は tree からの直接 lookup（`blob_at`）で行い、tree diff の再走査はしない。
- 出力は **unified diff のhunkテキスト**（`@@` ヘッダ + `-`/`+`/context行）。 gix が再エクスポートする imara-diff の `Diff::compute` と、gix-diff の `UnifiedDiff` シンク（`ConsumeHunk` 自前実装）で生成する。行単位の構造化JSONにしないのは、フロントの表示が行プレフィックスの色分けだけで足り、フォーマットは `git diff -u` として枯れているため。
- 先頭8000バイトにNULを含む場合は **binary** フラグを立て、本文を返さない。
- フロントエンドはファイルクリックでグラフ領域をdiffペインに置き換え、閉じるとグラフに戻る（詳細パネルは開いたまま）。

## Consequences

- 1クリック1リクエストで、リポジトリやコミットの規模に依存しない。
- 行内（文字単位）ハイライトやside-by-side表示はテキスト形式の外なので、必要になれば構造化レスポンスへの拡張（supersede）が要る。
- リネーム追跡を有効にしていないため、リネームは D + A の2ファイルとして見える。
