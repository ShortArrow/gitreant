# ADR 0023: 読み込みは一覧先行・リポジトリ並列・行ページングで段階化する

## Status

Accepted (2026-07-19)

## Context

`GET /api/repos` は全リポジトリを読み終えるまで何も返さないオール・オア・ナッシング構造で、巨大リポジトリが1つあると SPA は進捗表示のまま何も描けない。解析が詰まれば永遠に何も出ない。また全コミットを一括で SVG 行にする現在の描画は、10万コミット級では表示側も立ち行かなくなる。git には総コミット数を O(1) で返す仕組みがなく（コミットは DAG で台帳がない）、進捗の「%」は原理的に推定でしかありえない。

## Decision

- **一覧は即答する。** リポジトリの id/name/path はセッションが即座に知っているので、グラフ本体と分離した軽量応答でドロワーを最初から埋める。
- **グラフはリポジトリ単位の個別取得にし、クライアントが並列に読み込む。** 読み終わったリポジトリから順に表示が始まり、1つが詰まっても他は表示される。
- **進捗はコミットカウンタ（読了 N commits）に統一する。** 推定%とその分母永続化（CountCache）は誤った値を示し得る指標なので削除する（導入コミット f16ca24 / 29ae08a の該当部分を supersede）。
- **グラフ行はページングする。** 先頭 N 行（初期ページ）だけを返して即描画し、スクロール末尾到達で次ページを読み足す。表示順の安定が必須なので、ページはその時点までの表示順プレフィックスとしてサーバが返す。遅延の表示順ウォークには gix-traverse の topo ウォーカ（`--topo-order` 相当、世代番号ベース）を用いる。自前の walk+sort からの移行で行順が変わる場合はフィクスチャを追随させる。
- SSE の解析イベントはリポジトリ単位（id とカウンタ）に簡素化する。並列読み込みでは「何個目/全何個」は意味を失い、ドロワーの項目ごとのカウンタがそれを置き換える。

## Consequences

- 実装は3段階: (1) 一覧エンドポイントとリポジトリ単位ビューの追加（旧APIと共存）、(2) フロントエンドの並列読み込み化と旧API撤去、(3) topo ウォーカ移行と行ページング。各段階で全テストを緑に保つ。
- ページングにより「全コミット読了」を待たずに操作できるが、ページ末尾より下の行に依存する機能（squash 点線の対岸が未読等）は読み足しで解決するまで描かない。
- コミット数の事前推定が不要になったため、commit-graph ファイル等の近似手段は採用しない。
