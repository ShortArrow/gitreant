# ADR 0071: 同じマシンのほかのアカウントからサーバを守る

## Status

Accepted (2026-10-31)

## Context

QUALITY は、「同一マシンでの単一ユーザー利用が前提」であり、「リモート公開・多人数利用は範囲外」としていた。ところが、そのあとの二つの決定は、まさにマシンのほかの利用者から守るためのものである。[ADR 0063](0063-request-token.jp.md) は、ほかのアカウントがマシンを共有していたり、コンテナやサンドボックスがループバックを共有していたりすると、そのどれもがポートに届くとして、すべての API リクエストに秘密を求めた。[ADR 0064](0064-prove-the-secret.jp.md) は、サーバが止まったあとにはほかのアカウントのプログラムがポートを取れるとして、CLI がサーバに秘密の証明を求めるようにした。QUALITY の文と合わせて読むと、これらの守りは範囲外のものを相手にしていることになる。そのため、同じ攻撃者についての指摘（たとえば、ユーザーのサーバが去ったポートから配られるページ）は、一方の文書では退けられ、もう一方では求められうる。

## Decision

- **マシンのほかのアカウントは範囲内とする。** QUALITY は、ほかのアカウントや、マシンのループバックを共有するコンテナやサンドボックスが、サーバのポートに届き、サーバが去ったポートを取れるものとする。ユーザーのファイルやメモリを読めるとはしない。秘密は、ユーザーだけが読めるファイルに置かれる。
- **ユーザーはこれまでどおり一人であり、** 開いたリポジトリの内容は、QUALITY のとおり引き続き信頼する。リモート公開は範囲外のままとする。

## Consequences

- ほかのアカウントがポートに届く、サーバが去ったポートで応える、ページのオリジンからページを配る、といった指摘は、範囲内として扱う。
- ADR 0063 と ADR 0064 は、QUALITY に反するのではなく、QUALITY が述べる前提の上に立つ。
