# 品質保証と提供責任

[English](QUALITY.md) | [日本語](QUALITY.jp.md)

gitreant のセキュリティの前提、品質ゲート、提供するサービスの責任範囲の単一ソース。

## セキュリティ

セキュリティは、機能要件と非機能要件のすべての前提とする。機能は、費用や使い勝手を比べる前に、外からの入力がプログラムの実行、ファイルの読み書き、マークアップの描画に届く新しい経路を開かないように設計する。

### 信頼境界

- サーバは 127.0.0.1 にのみバインドする。ループバックの名前宛てのリクエストにだけ応え、状態を変えるのは自分のページか、ページでないクライアントからのときだけである（[ADR 0038](adr/0038-loopback-request-guard.jp.md)）。
- `/api/` 以下のリクエストはすべて、サーバが起動ごとに OS の乱数源から作る秘密を持つ。秘密が要らないのは、gitreant が応えることだけを返す `/api/ping` だけである。CLI は、動いているサーバが秘密を持つことを示してから信頼する（[ADR 0063](adr/0063-request-token.jp.md)、[ADR 0064](adr/0064-prove-the-secret.jp.md)）。
- 同一マシンでの単一ユーザー利用が前提。リモート公開・多人数利用は範囲外で、リバースプロキシ等で公開した場合の安全性は保証しない。
- 開くリポジトリの内容（`.gitmodules`・ref 名・パス・git の設定等）はユーザーが信頼したものとみなす。submodule の宣言先が妥当かどうかは、そのリポジトリの管理者が責任を持つ。gitreant は宣言されたパス（`.git` を持つディレクトリに限る）を読み取り専用でグラフに描くだけで、素の git 以上の隔離は行わない。信頼できないリポジトリ内容から自身を守るのは範囲外とする。

### すべての機能が守る決まり

- リクエストが実行するプログラムを選べるのは、ユーザーが設定した一覧の中の位置によってだけとする。リクエストの中身は、引数としてだけコマンドに渡し、シェルを通さない。
- 新しいエンドポイントは `/api/` 以下に置き、秘密の検査の内側に入れる。
- リクエストは、求める処理のほかに外部プロセスを起動しない。ツールのバージョンのように、どのリクエストでも同じものは、プロセスごとに 1 回だけ調べる。
- セキュリティについての主張は、コードの経路で確かめ、できるところは、守りを外すと失敗するテストで確かめる。

## 品質ゲート

| タイミング | 必須にするもの |
|---|---|
| 毎 push | `cargo test`（unit＋統合）、frontend の `tsc -b` / `vitest run` / `vite build` がすべて green。バグ修正は再現テストを先に書く（Red→Green） |
| 機能マイルストーン毎 | E2E フルスイート green。UI 機能のまとまりが完了した時点、または E2E 未実行の機能が複数溜まった時点で実行する |
| リリース/タグ前 | E2E フルに加え `pnpm screenshot` のアサーション green（README 掲載機能の可視回帰） |

E2E の運用制約: スイートは直列1本で走る。実行中のテストが参照しているため、スイートの実行中は `frontend/dist` の上書きとバイナリのビルドを行わないこと。

## 提供サービスの責任範囲

### データ安全

- リポジトリへの書き込みは、fetch / checkout / merge / ブランチ作成 / タグ作成・削除 / stash の閲覧という明示操作に限る。
- 履歴改変（rebase・amend・reset）、強制 push、ブランチ削除、作業ツリーのファイル削除は提供しない。この方針の変更には ADR を要する。
- バックグラウンドの読み取りは、`GIT_OPTIONAL_LOCKS=0` 等を使い、並行する手元の git 操作と競合しないように実装する。

### 外部依存と劣化動作

| ツール | 位置づけ | 欠けたとき |
|---|---|---|
| git | 必須 | 起動不能相当。`gitreant doctor` が報告する |
| gh | 任意 | PR リンク・squash 点線・アバター検索が静かに消える |
| gpg | 任意 | 署名は「Signed」表示のみで検証されない |

診断の単一窓口は `gitreant doctor`。

### ネットワーク送信

外部と通信するのは次の4経路のみ。テレメトリ・利用状況の送信は行わない。

- `git fetch` — ユーザーが設定したリモートに対して
- `git ls-remote` — 同上
- `gh` CLI — GitHub API（ユーザー自身の認証で）
- アバター画像の取得 — avatars.githubusercontent.com / github.com（ブラウザから。設定でオフにできる）
