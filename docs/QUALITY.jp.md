# 品質保証と提供責任

[English](QUALITY.md) | [日本語](QUALITY.jp.md)

gitreant の品質ゲートと、提供するサービスの責任範囲の単一ソース。
決定の経緯は [ADR 0024](adr/0024-quality-and-responsibility.jp.md)。

## 品質ゲート

| タイミング | 必須にするもの |
|---|---|
| 毎 push | `cargo test`（unit＋統合）、frontend の `tsc -b` / `vitest run` / `vite build` がすべて green。バグ修正は再現テストを先に書く（Red→Green） |
| 機能マイルストーン毎 | E2E フルスイート green。UI 機能のまとまりが完了した時点、または E2E 未実行の機能が複数溜まった時点で実行する |
| リリース/タグ前 | E2E フルに加え `pnpm screenshot` のアサーション green（README 掲載機能の可視回帰） |

E2E の運用制約: スイートは直列1本で 10〜17 分かかる。実行中は
`frontend/dist` の上書きとバイナリのビルドを行わないこと
（実行中のテストが参照している）。

## 提供サービスの責任範囲

### 信頼境界

- サーバは 127.0.0.1 にのみバインドし、認証を持たない。
- 同一マシンでの単一ユーザー利用が前提。リモート公開・多人数利用は
  範囲外で、リバースプロキシ等で公開した場合の安全性は保証しない。

### データ安全

- リポジトリへの書き込みは明示操作のみ:
  fetch / checkout / merge / ブランチ作成 / タグ作成・削除 / stash の閲覧。
- 履歴改変（rebase・amend・reset）、強制 push、ブランチ削除、
  作業ツリーのファイル削除は提供しない。この方針の変更には
  ADR を要する。
- バックグラウンドの読み取りは `GIT_OPTIONAL_LOCKS=0` 等で
  並行する手元の git 操作と競合しないよう実装する。
- 開くリポジトリの内容（`.gitmodules`・ref 名・パス等）はユーザーが
  信頼したものとみなす。submodule の宣言先の妥当性はそのリポジトリの
  管理者の責任であり、gitreant は宣言されたパス（`.git` を持つ
  ディレクトリに限る）を読み取り専用でグラフ描画するのみで、
  素の git 以上の隔離は行わない。信頼できないリポジトリ内容から
  自身を守るのは範囲外とする。

### 外部依存と劣化動作

| ツール | 位置づけ | 欠けたとき |
|---|---|---|
| git | 必須 | 起動不能相当。`gitreant doctor` が報告する |
| gh | 任意 | PR リンク・squash 点線・アバター検索が静かに消える |
| gpg | 任意 | 署名は「Signed」表示のみで検証されない |

診断の単一窓口は `gitreant doctor`。

### ネットワーク送信

外部と通信するのは次の4経路のみ。テレメトリ・利用状況の送信は行わない。

- `git fetch` / `git ls-remote` — ユーザーが設定したリモートに対して
- `gh` CLI — GitHub API（ユーザー自身の認証で）
- アバター画像の取得 — avatars.githubusercontent.com / github.com
  （ブラウザから。設定でオフにできる）
